## 漏洞 A：ring3 无内存隔离 🟡（阶段 1 已实现，默认关闭，待 QEMU 验证）

**旧报告的错误结论**：「独立 PML4 + CR3 切换 = 已修复」。

**源码核对后的真实情况**：
1. `fork` 创建的是**共用地址空间的内核线程**，并不复制用户地址空间。
2. 每个进程的 PML4 只复制内核 PML4 表项，PDPT/PD/PT 下层表实际是**共享**的（`user_process.c` 的 `create_user_page_table_with_code`）。
3. `sys_brk` 只修改一个记录变量，**并不真正映射物理页**。
4. 进程退出时页表与用户页帧**不释放**（`user_process_release` 注释「页表保留」）。
5. 内核位于**低半区**（0x100000 起），物理内存恒等映射带 `PAGE_USER`（`vmm64.c`），用户程序可直接寻址。

**结论（默认构建）**：用户程序通过普通 load/store（而非系统调用）**仍可直接读写内核内存和其他进程的内存**。

### 阶段 1：私有页表 + 内核映射 ring3 不可访问（已实现，默认关闭，待 QEMU 验证）

- 新文件 `kernel/arch/x86_64/user_aspace64.c`：每个进程拥有私有 PML4/PDPT；内核映射（PML4[1..]、PDPT 里的全部内核表项）在进程视图里清除 U/S 位，下层 PD 仍与内核共享，所以内核（ring0）在任何进程的 CR3 下照常工作；用户窗口 `[0x40000000, 0x80000000)` 的 PD/PT 由 `vmm64_map_page` 在私有 PDPT 下新建，只属于该进程。
- 进程正常退出或被终止时回收页帧、PT、PD、PDPT、PML4（识别规则：隔离模式下 U/S=1 的 PDPT/PD 表项一定是本进程创建的；CR3 仍指向它时拒绝释放）。进程记录仍保留，任务管理器行为不变。
- 开启：`make USER_ISOLATION=1`（默认关）。仅作用于 ELF 进程（`user_process_exec`）；以内核函数为入口的内置测试进程（`user_process_create`，如 `user_program_hello`）需要 ring3 执行内核镜像，始终走旧模式。
- 条件不满足时自动退回旧模式并打印日志：物理内存 > 1GB（恒等映射覆盖用户窗口）。**QEMU 请用 `-m 512` 以内**；ELF 代码段落在用户窗口之外时拒绝加载。
- 顺带修复：`user_process_exec` 之前每次都泄漏内核堆里的 ELF 镜像副本（最多 16MB），现在复制进用户页后 `kfree`。
- **主机端验证**（`tools/host-tests/aspace_test.c`：真实 `vmm64.c` + `user_aspace64.c` + 软件 MMU 模拟四级页表遍历）：
  - ring3 访问恒等映射、内核镜像、帧缓冲/APIC 类 MMIO 一律缺页，ring0 在进程 CR3 下的翻译与内核 CR3 完全一致；
  - 两个进程在同一虚拟地址的映射指向各自不同的页帧，改动不会写进内核页表（逐页快照比较）；
  - 释放只回收本进程的页（逐页校验归属，无重复释放、无误释放内核页或其他进程的页），回收后内核页表和另一进程不受影响；
  - RAM > 1GB 退回旧模式；对照组复现了旧实现缺陷：进程映射出现在内核页表里、第二个进程覆盖第一个、ring3 可写内核镜像。
- **QEMU 回归清单（打开 `USER_ISOLATION=1` 后）**：正常启动和桌面；`exec` 常用程序；`sec_test`；一个故意读/写内核地址（如 0x100000）的用户程序，应只被终止并回到桌面；连续 `exec` 多个程序互不影响；任务管理器 kill；连续 exec 20 次观察空闲页不持续下降。

### 阶段 2：尚未完成

1. `fork` 仍是共用地址空间的内核线程（在父进程 CR3 下运行），需改为复制地址空间。
2. 物理内存 > 1GB 时用户窗口与内核恒等映射冲突，目前只能退回旧模式。
3. ~~内核自身 CR3 映射带 U/S 位导致不能开 SMEP/SMAP~~ SMEP/SMAP 已启用并按 CR4 真实状态门控（见 SEC-06）；内核 PML4 内核映射去 U/S 位的其余清理仍待确认。
4. 以内核函数为入口的内置测试进程仍走旧模式。
5. 进程创建后内核新增的 PDPT 级表项（>=4GB 或新的 1GB 槽位的 MMIO）不会出现在已创建进程的私有 PDPT 里；创建时只预建了 PDPT[2]、[3]。
6. ~~`sys_brk` 不映射页 / NX 未做 / 退出不回收~~ `sys_brk` 已按需映射堆页并带 NX（`:1678-1694`）；进程记录正常退出回收已闭环（SEC-09 已关闭）。

## 漏洞 C：用户指针无校验 🟡（主要路径已加固）

**修复内容**（`user_access64.c`）：
- `copy_*_user` 只接受严格用户窗口 `[0x40000000, 0x80000000)`；旧实现把内核（0x100000 起）和整个物理内存恒等映射都算作「用户范围」。
- 拷贝前走当前 CR3 的四级页表，逐页校验：已映射（P）、用户可访问（U/S）、写入时可写（R/W）；支持 4KB / 2MB / 1GB 页。
- 旧实现传「范围内但未映射」的地址会触发缺页并 `hlt` 整机死机；现返回错误。
- 编译开关 `HEPU_STRICT_USER_RANGE`（默认 1；ring0 自测需用内核指针调用系统调用时可设 0）。

**待办**：全量审计所有系统调用的用户指针是否都经 `copy_*_user`。

## 漏洞 D：数组越界写 🟡

- `syscall64_full.c`：路径按字符串长度复制并强制 NUL、超长（≥255）拒绝；`lseek` 拒绝负偏移（旧实现可让 `sys_read` 读 `file_buf` 之前的内核内存）；裸盘 LBA 不再被截断成 32 位；未知调用号的打印缓冲区溢出已修复。
- `elf64.c`：完整边界与溢出检查，入口点必须落在 `PT_LOAD` 且为规范用户地址，不再保留指向调用方缓冲区的悬空指针。
- `ext2_algo.c` / `ext2_64.c`：挂载前校验超级块；目录项、块指针、组号、位图、`i_block` 下标均做范围检查。
- `kheap64.c`：修复非首块 `kfree` 全部失败（内存只增不减）；尺寸/乘法溢出检查；块头 48 字节 16 字节对齐；magic 与块地址绑定；safe-unlink；关中断 + 自旋锁。
- `syscall64_simple.c`：SFMASK 除 IF/DF 外还清 TF、NT、AC。
- `syscall64_full.c` 的 `sys_exit`：退出码由用户程序决定，原来的 `char tmp[8]/buf[8]` 对 8 位以上的值会写穿内核栈（与未知调用号打印同类问题），已改用安全打印。
- `user_process.c`：进程入口初始 RSP 为 8 (mod 16)，符合 GCC 对 C 编写的 `_start` 的假设，修复内联系统调用 `movaps` 触发 #GP。

## 追加修复（代码已改，**待 QEMU 验证**）

1. **每进程 fd 表**：旧实现是全局单表，任意进程可对其他进程打开的 fd 做 read/write/close/lseek。现按用户进程槽位隔离，进程释放时清空（`syscall64_full.c`、`user_process.c`）。fork 子线程共享父进程槽位，行为与之前一致。
2. **`sys_kill` 只能终止自己**：旧实现允许任何用户进程按 pid 终止任意进程。项目目前没有 uid/权限模型，先做最小权限；任务管理器和 Ctrl+Alt+K 走内核直接调用，不受影响。
3. **用户态异常只终止该进程**（`lib64.c`）：旧实现任何 ring3 异常（空指针、非法指令、#GP、#PF）都让整机 `hlt`。现在复用 V0.13.46 强制终止机制回到桌面；NMI/#DF/#MC 与内核态异常仍然停机。

**行为变化，QEMU 回归请重点看**：
- `sys_write` 拒绝只读打开的 fd，`sys_read` 拒绝只写打开的 fd。
- 路径长度 ≥255 被拒绝（旧实现静默截断）。
- ext2 目录中已删除条目（inode=0）现在被跳过继续查找（旧实现在此中断，删除后后续文件不可见）。
- 严格用户窗口：若有 ring0 自测用内核指针调用系统调用，会被拒绝。
- 回归项：`exec`/`fork`、桌面、一个故意解引用空指针的用户程序（应只被终止并回到桌面）、`kill` 自己与他人、两个进程的 fd 互不可见、挂载 1K/4K ext2。

## 其他未修复项（已登记 OPEN_BUGS SEC-02 至 SEC-06）

- `entry_64.S` 用全局变量（`g_syscall_ret_rip`、`g_syscall_kernel_rsp`、`g_syscall_ustack_slot`）保存系统调用上下文，非 per-CPU/per-task；多核或阻塞后切换进程会互相覆盖。
- 裸盘读写/reboot/mkfs 已加 PID==0 临时闸（拒绝所有真实用户进程，PID 恒 ≥100，口径见 OPEN_BUGS PID 注记）；uid/capability 能力模型仍未落地，安装器/分区工具的长期授权随该模型解决（SEC-04、OPEN-04）。
- 主路径缓冲（`kernel_buf`/`file_buf`/`elf_buffer`）已改为调用期 kmalloc；`sys_readdir` 静态 names/types 表仍不可重入；内核栈仅 4KB 的约束仍在（SEC-05）。
- 内核态缺页仍然 `hlt`；NX/W^X/SMEP/SMAP 已启用并按 CR4 真实状态门控（见 SEC-06），内核态缺页停机策略未改。
- 文件系统无访问控制位，`open` 不做路径规范化。

## 代码卫生

- `kernel/arch/x86_64/syscall64.c` **未编入 Makefile**（实际生效的是 `syscall64_simple.c` + `syscall64_full.c`），建议删除或标注废弃，避免审计误判。
- ext2 挂载后 `ext2_use_shared_algo = 1`，实际解析在 `kernel/shared/fs/ext2_algo.c`，`ext2_64.c` 内的旧解析函数基本不执行。
- `process64_full.c` 与 `user_process.c` 两套进程实现并存。

## 测试集成

`/bin/sec_test.elf` 的启动自动运行已放到编译开关 `HEPU_BOOT_SELFTEST` 之后，**发布构建默认关闭**；回归时用 `make BOOT_SELFTEST=1` 打开。打开后 `kernel_main_64.c` 与 `shell64.c` autostart 各同步运行一次（`user_process_exec` 会阻塞到进程退出，测试程序挂起会阻塞启动），确认哪一处更合适后建议只保留一处。

## 不适用漏洞（功能未实现）

- **E（signal）/ F（沙箱）/ H（共享内存）**：对应功能尚未实现，须在功能落地时同步加入校验（handler 地址必须在用户窗口、文件系统调用统一走沙箱检查、shm 带权限位）。

## 安全增强建议（按优先级）

### P0
1. **完成漏洞 A 的页表隔离**（ROADMAP P0-6）——当前唯一的致命项。
2. 栈金丝雀（Stack Canary）。

### P1
1. 全量审计系统调用的用户指针与输出内容。
2. 信号 / 沙箱 / 共享内存实现时同步加入校验。
3. 建立 uid/capability 与文件权限模型，再收紧 `sys_kill` 与裸盘读写。

### P2
1. KASLR；SMEP/SMAP；类 seccomp 系统调用过滤。

## 结论

- 系统调用路径上的用户指针校验与多处输入校验（ELF/ext2/堆/fd）已建立，其中用户指针校验经 QEMU 基础回归，其余主要经主机端测试，追加修复尚待 QEMU 验证。
- **漏洞 A（ring3 内存隔离）**：阶段 1（私有页表 + 内核映射不可访问）已实现、**默认开启**并通过 QEMU 回归（512MB/1.5GB 到桌面、sec_test 通过，见 OPEN_BUGS SEC-01）；SMEP/SMAP 已启用并按 CR4 真实状态门控（见 SEC-06）。阶段 2 仍未做：fork/clone 复制私有地址空间（现共享父进程页表指针，COW 未接入，见 SEC-02）、RAM>1GB 冲突、内核自身 CR3 映射去 U/S 位。
- 不再给出总分：此前的 85/100 基于错误前提，首版重写的 55/100 也没有评分标准。以上逐项状态为准。
