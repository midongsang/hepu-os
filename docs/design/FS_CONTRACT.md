# FS 契约（32/64 位共享 ext2）

> 版本：2026-11-23。状态：生效。
> 配套测试：`tools/fs_conform.sh`（同一张盘，32 位写→64 位读→64 位写→32 位读）。

## 1. 这份契约管什么

HepuOS 有两套完全独立的 ext2 实现：

- 32 位：`kernel/fs/ext2*.c` + `ide_ext2.c`，对外是 VFS（`vfs_open/read/write/readdir`）
- 64 位：`kernel/arch/x86_64/ext2_64.c`，对外是 `ext2_64_*` 直调，没有 VFS

**契约只约束“盘上的结果”，不约束 API。** 两套实现可以继续各自演进，
但写出来的 ext2 结构必须能被对方正确读取；反之亦然。

## 2. 必须满足的不变式

### 2.1 块大小

- 块大小一律从超级块 `s_log_block_size` 推导，**不允许硬编码 1024**。
- 当前已验证：1024 字节块（32 位验证盘）与 4096 字节块（64 位共享镜像）都能双向读写。

### 2.2 文件内容

- 写入 N 字节，读回应**恰好**是 N 字节，内容逐字节一致。
- 读取接口可以有“文本模式”（为 `\0` 留一位），但调用方必须知道这一点：
  判定“内容正确”时要用实际字符串长度，**不允许手写魔数**。
  （教训：`VS_LEN` 曾手写成 9，而串有 10 个字符，写少一字节、比少一字节，自洽地一直 PASS。）

### 2.3 目录项

- 遍历目录必须跳过 `inode == 0` 的已删除项与 `.` / `..`。
- 删除文件必须让目录项 `inode` 置 0，并保证后续遍历不再列出该名字。
- 文件名在盘上最长 255 字节；VFS 层限制 `VFS_MAX_NAME`（64），两者不冲突，
  但跨层传递时必须显式截断。

### 2.4 元数据一致性

- 分配/释放块或 inode 后，超级块与 GDT 的 `free_blocks_count` / `free_inodes_count`
  必须同步更新并落盘，不能只改内存副本。
- 块位图中“块 0 / 引导块”位必须恒为已用；读出为 0 视为位图损坏，拒绝继续分配。
- 元数据块（超级块、GDT、块位图、inode 位图、inode 表）**永远不可作为数据块分配**。

### 2.5 同步语义

- `sync` 完成后，已写入的数据与元数据必须能在下一次独立启动中读到。
- 32 位：`vfs_sync()` → `ide_ext2_sync()`。
- 64 位：写路径直接更新盘上 GDT/超级块（`ext2_algo_*` 共享算法）。
- `sync` 不等于掉电安全；掉电一致性由单独的测试与 `fsck` 策略负责（见 D3）。

### 2.6 错误语义

| 场景 | 约定 |
|---|---|
| 打开不存在文件（只读） | 返回负值（`ENOENT` 语义） |
| 创建已存在文件（带 `O_TRUNC`） | 截断后写入；当前 32 位 `vfs_open` **忽略** `O_TRUNC`，是已知偏差 |
| 目录当文件读 | 返回负值 |
| 位图损坏 | 拒绝分配并打印错误，不静默写坏盘 |

## 3. 当前已验证的部分（`tools/fs_conform.sh`）

序列：

1. 32 位启动 → 写 `/c32.txt = "FROM_32BIT"` → 回读校验
2. 64 位启动 → 读 `/c32.txt` → 写 `/c64.txt = "FROM_64BIT"` → 回读校验
3. 32 位启动 → 读 `/c64.txt` 校验

实测输出：

```
[CONFORM32] write_c32 len=10
[CONFORM32] PHASE_C RESULT: PASS
[CONFORM64] read_c32=FROM_32BIT
[CONFORM64] verify_c64=FROM_64BIT
[CONFORM32] read_c64=FROM_64BIT
[CONFORM32] PHASE_D RESULT: PASS
```

## 4. 还没有覆盖的（写清楚，别假装有）

- 并发写（两套实现同时挂同一张盘）——当前不支持，也不承诺
- 崩溃/掉电中途的契约（见 D3 的 `cache=unsafe` 测试）
- `rename` / `mv` 的跨实现行为
- 大于 12 个直接块、走间接块的文件
- 1024 字节块上“64 位写、32 位读”的反向组合（目前反向用的是 4096 字节块）
- 符号链接、稀疏文件、扩展属性

新增实现或修改任一侧的 ext2 代码后，**必须重跑 `tools/fs_conform.sh`**，
并在提交信息里贴出 `[CONFORM] RESULT: PASS`。
