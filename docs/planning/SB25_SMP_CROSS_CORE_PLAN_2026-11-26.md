## 一、范围与约束

### 1.1 本文回答的问题

SB-25 在 SMP 硬化包中的原始定位是「放开 AP 调度、每核运行队列、唤醒 IPI、
迁移策略」（见 [PLAN_SMP_HARDENING_R5.md](./PLAN_SMP_HARDENING_R5.md) §阶段 5
与 [../status/OPEN_BUGS.md](../status/OPEN_BUGS.md) SEC-20 小节）。本文只做三件事：

1. 盘点 64 位侧调度器、进程表、AP 启动、APIC/IPI、clone 线程在当前 HEAD 的真实
   代码现状（附锚点）；
2. 给出跨核调度的目标模型、最小可落地闭环与分阶段路线图；
3. 列出关键风险清单，每条按「触发条件 — 后果 — 缓解手段 — 验证方法」四段描述。

### 2.4 与 SEC-02 / SEC-20 的边界（台账既有记录）

> 以下两条为 OPEN_BUGS.md 的既有台账结论，本文只做边界衔接，不在本轮重新复核其
> 运行时证据。

- **SEC-02**（`../status/OPEN_BUGS.md` 主表 SEC-02 行）：fork 已接入 COW；clone
  共享父页表，单核内用户线程调度闭环；跨核调度与收尾边界指向 SEC-20 / SB-25。
  对应到代码：共享页表记账见 `user_process.c:173,2303-2315`，COW 缺页框架在
  `vmm64.c`（台账所引 `vmm64_try_cow`）。
- **SEC-20**（`../status/OPEN_BUGS.md` SEC-20 小节）：用户线程作为调度单元的功能
  层在单核内闭环；剩余问题是跨核并发——用户线程只在当前运行核上轮转，跨核调度、
  线程状态的跨核隔离属 SB-25 范围。

## 三、目标模型（方案，未验证）

> 本章描述「计划演进到的形态」。下列结构与策略在当前 HEAD 中**尚未成型**；
> 现状与目标的差距已在第二章锚点中标出。

### 3.1 每核运行队列（per-CPU rq）

- **现状**：单一全局 `ready_queue[5][64]` 配一把 `g_sched_lock`（2.1 节）。
- **目标**：
  1. 调度就绪状态按核拆成 `rq[cpu]`，每队列一把独立小锁；PCB 上保留 `running_on`
     归属标记作为跨队列一致性的第一道防线；
  2. 本核调度只扫描本核 rq，候选收集 / 出队 / 计数更新在本核队列锁内完成；
  3. 全局调度锁只在需要跨核操作（迁移、窃取、队列间搬运）时持有，临界区尽量短；
  4. 队列条目去重与归属不变量：一个任务同一时刻只存在于一个 rq，`running_on`
     与队列归属一致。
- **设计约束**：`process_t` 布局被 `_Static_assert` 钉住（`process64_full.c:94-95`），
  新增调度字段优先放在独立 per-CPU / 辅助结构，不贸然挪动现有上下文偏移。

### 3.2 任务亲和与迁移策略

- **亲和初始值**：创建时的轮询分配（`process64_full.c:419-424`）保留为初始放置
  策略；同进程的 clone 线程默认保持同核亲和（共享页表 / 共享用户栈上下文，跨核
  迁移成本与竞态面更大，见风险 R2/R7）。
- **迁移条件（候选）**：仅在源核过载、目标核空闲、且任务无不可迁移约束时考虑；
  迁移走显式协议（摘源队 → 交接归属 → 重绑栈/FS/GS/FPU → 入目标队），不允许
  两核同时从各自队列拿到同一个任务。
- **不可迁移项**：每核专属 idle（`proc_is_cpu_idle`，`process64_full.c:201-206`）、
  持有内核专属上下文 / 桌面对 owner 的线程，在 owner 契约边界完成前不参与迁移。

### 3.3 唤醒 IPI 与 TLB shootdown 需求

- **重调度 IPI（RESCHEDULE）**：通道与接收分发已在源码中存在（`smp.c:49,387-394`），
  但**尚无发送方**。目标形态：唤醒一个不在本核运行的任务时，入队与「判断目标核
  是否需要被叫醒」在同一临界区内完成；目标核处于 idle 或时间片未用尽时，向其
  发送 `RESCHEDULE`，由其在中断返回前 / 下一次 tick 前重新进入调度。
- **TLB shootdown**：页表修改路径已接 `vmm64_flush_tlb_others()`（`vmm64.c:68-81`）。
  跨核迁移与共享地址空间场景下，凡涉及 CR3 切换、页表项改写、COW 拆页、权限回收，
  都必须保证先完成跨核刷新汇聚再继续；中断上下文不得走同步等应答的发送路径
  （沿用 `vmm64.c:46` 的现有约束）。
- **唤醒与刷新的顺序**：先改调度归属 / 队列，再发对应 IPI；IPI 槽忙时计入 dropped
  计数并由调用方决定重试或退回本地 tick 兜底，不覆盖待处理消息。

### 3.4 idle 与 work stealing 的取舍

- **idle 语义**：每核专属 idle 不进 rq，只在本核无候选时切回（现状回退分支
  `process64_full.c:940-962`）。idle 核可以响应中断、收 IPI、跑本地惰性任务，
  但不主动持有用户任务上下文。
- **窃取（work stealing）**：现状的跨核兜底扫描（`895-938`）是「共享队列下的
  被动挑闲」；目标模型中窃取应是 per-CPU rq 之间的**受限**动作：仅空闲核、仅在
  本核 rq 为空时尝试，单次窃取条目数有限，优先取同亲和 / 同域任务。
- **取舍倾向**：S2 阶段先关闭跨核窃取（AP 只跑本核 idle），把「AP 进入调度循环、
  定时器与中断正常」打通；S4 再开受限窃取。理由见 3.5。

### 3.5 最小可落地闭环（风险最低的第一步）

**闭环定义**：AP 完成上电 → 进入本核调度循环 → 定时器中断正常计数 → 无候选时
切回本核专属 idle 并 `hlt`；**不从 AP 核取其他核的任务，不做跨核迁移，不开放
用户线程跨核调度**。

- **先做这一步的理由**：
  1. 把「核间并发」压缩到最小接触面——AP 上只有 idle 上下文，不触碰用户页表、
     fd 表、线程现场，共享状态竞态面被限制在中断计数与 IPI 应答层；
  2. 可独立观察：AP 是否到位、定时器是否走、是否回到 idle、BSP 桌面是否不受影响，
     每一项都有串口可判；
  3. 出问题可直接退回现状 AP `hlt` 循环（`smp.c:270-272`），不牵连用户任务；
  4. 跨核窃取 / 迁移 / 线程轮转全部后置，避免在栈隔离、current 归属、唤醒 IPI
     尚未收口时同时暴露多类竞态。
- **不在闭环内的事项**：任务跨核分布、负载均衡、clone 线程跨核、阻塞唤醒跨核
  通知，均留到后续阶段。

## 四、关键风险清单（按严重度排序）

> 每条四段：**触发条件 / 后果 / 缓解手段 / 验证方法**。验证方法均为计划内的未来
> 验收动作，本轮不执行、不给出通过结论。

### R1（P0）共享就绪队列的锁瓶颈、饥饿与出队竞态

- **触发条件**：多核并发进入入队 / 出队 / 调度选择；高优先级任务持续就绪，低优先级
  任务长期排在队尾；两核在「选中 → 摘队 → `running_on` 交接」窗口交叉进入。
- **后果**：调度吞吐被单把全局锁串行压住；队列条目重复入队 / 出队错位；同一任务
  被两核同时选中后上下文互相覆盖；低优先级任务饥饿，`runtime` 统计长期不增长。
- **缓解手段**：按 3.1 拆 per-CPU rq 与队列小锁；归属过滤与摘队保持在同一锁内；
  保留 `running_on` 交接校验；补充按优先级 / 等待时长的饥饿观测，超时再提权或
  迁移；锁内不做阻塞等待、不做上下文切换（沿用现有 `g_sched_lock` 约束）。
- **验证方法**：（未来）多核压测创建 / 退出 / 轮转，队列无重复条目、无空指针选中；
  锁等待与持有者可观测；各优先级任务 `runtime` 均有增长；BSP 单核心调度行为不回归。

### R2（P0）clone 共享页表在多核下的 TLB / COW 竞态

- **触发条件**：同一地址空间的两条线程被调度到不同核；一核做 COW 拆页 / 权限
  修改 / 解除映射，另一核同时访问该页；`g_pt_ref` 跨核并发增减；父进程退出与
  子线程在另一核运行交错。
- **后果**：他核 TLB 残留旧映射，访问已失效或已改归属的物理页；COW 双份拆页
  竞争产生脏页；引用计数丢失导致页表被提前释放，触发 #PF 或串内存；故障高度随机、
  跨核交叉踩内存，单线程栈回溯难以定位。
- **缓解手段**：跨核迁移前默认同进程线程绑定同核亲和；页表修改路径统一走
  `vmm64_flush_tlb_others()` 并汇聚应答；`g_pt_ref` 改原子计数；释放地址空间前
  先确认无他核运行（快照 + 必要时 STOP IPI 收拢），再回收；共享页表的 COW 标记 /
  引用位改动纳入锁或原子保护。
- **验证方法**：（未来）多核并发 mmap / munmap / COW 缺页压测，无残留访问、无重复
  物理页；引用计数与存活线程数对账一致；TLB_FLUSH 发送数与 ack 数对账；故障样本
  含核号与页表地址。

### R3（P0）内核栈与 current 指针的 per-CPU 化缺口

- **触发条件**：两核同时进系统调用；两核同时轮转用户线程；调度切换时当前进程 /
  线程槽位被另一核覆盖。现状 `current_user_proc` 为全局单值（`user_process.c:137`），
  `g_ut[]` / `g_ut_cur` 为全局单份（`uthread64.c:41-42`）。
- **后果**：系统调用拿到别核进程的 fd 表 / 页表 / 凭据；线程现场保存到别人槽位，
  恢复时 rip/rsp/GPR 错位；内核栈串栈，表现为随机 #PF / #GP / #DF，且复现概率随机。
- **缓解手段**：`current_user_proc` 迁入 per-CPU 区或随进程上下文携带，切换点成对
  绑定（与现有 fork 快照绑定路径同构，`process64_full.c:877-878`）；uthread 调度
  状态按 owner / 核拆分，轮转与保存现场不共享全局游标；补启动期断言：各核栈槽 /
  当前槽互不相同。
- **验证方法**：（未来）多核并发系统调用（write / brk / mmap / fork），各核内核栈
  指针与当前进程槽互不相同；无 #SS / #DF；切换前后槽位与 PCB 一致；单核心路径
  不回归。

### R4（P1）AP 中断与定时器校准偏差

- **触发条件**：AP 定时器 ICR 校准不准或校准失败退回保守值；核间 tick 频率不一致；
  校准基准在不同拓扑下缺失（历史相关问题见台账 BUG-49 / BUG-52 记录）。
- **后果**：AP 时间片过快 / 过慢，`runtime` 与 CPU 占用统计失真；看门狗误判任务
  挂起或漏判真正卡死的任务。
- **缓解手段**：每核记录自己的定时器频率与校准来源，启动诊断按核 ID 打印；校准
  失败显式报核号与回退路径；跨核时长统计走全局原子 tick，不依赖各核本地计数
  直接对账。
- **验证方法**：（未来）多核启动后每核本地 tick 计数单调不减；校准来源 / 频率可
  串口打印；长时间运行无 tick 倒退、无校准告警刷屏；看门狗判定与实际运行时长
  对账。

### R5（P1）跨核唤醒丢失（lost wakeup）

- **触发条件**：任务在核 A 阻塞，核 B 上的事件源将其唤醒；就绪项进入队列后，
  目标核正处于 idle `hlt`，本地 tick 尚未到达。现状 `process64_wakeup()` 只入队、
  不发重调度 IPI（`process64_full.c:1064-1077`），`RESCHEDULE` 也无发送方。
- **后果**：任务滞留 READY 态不被运行，外层表现为「任务卡死」；唤醒延迟依赖下一次
  本地 tick，时序不可控；若目标核长期 idle，延迟被放大。
- **缓解手段**：wakeup 路径在同一锁内判断目标核状态，必要时发 `RESCHEDULE`；
  IPI 槽忙时计入 dropped 并可重试；保留本地 tick 作为兜底唤醒；READY 滞留时长
  纳入诊断统计。
- **验证方法**：（未来）构造跨核阻塞 → 唤醒场景，目标核在一个 tick 内被叫醒调度；
  IPI ack 与发送数对账；dropped 计数为 0 或有补偿重试；无任务长时间滞留 READY。

### R6（P1）调试与取证手段缺失：串口单通道、无 per-CPU 日志

- **触发条件**：多核并发打印，两核输出交替写同一串口；故障发生后只有一串交织的
  串口流，无法按核回溯是哪一核改了哪项状态。现状 AP 早期串口靠 `print_lock` 串行
  （`smp.c:128-139`），诊断行拼整串输出（`smp.c:287-314`），但无每核日志缓冲。
- **后果**：日志半行交错掩盖症状；跨核竞态现场无法按核号 / 时序还原；故障归因
  只能靠猜，返工成本高。
- **缓解手段**：增设轻量 per-CPU 日志槽（核 ID + 序号 + 关键字段），诊断信息一次
  成串输出；保留 per-CPU tick / IPI ack / dropped / 队列长度快照接口；故障 dump
  必须带核号、APIC ID、当前 PCB 索引。
- **验证方法**：（未来）多核并发打印无半行交错；日志可按核 ID 过滤；异常样本包含
  核号与关键上下文；启动期快照与运行期计数可对账。

### R7（P2）迁移过程中的上下文 / 页表 / FPU 一致性

- **触发条件**：任务从核 A 迁到核 B；旧核尚未存完现场、新核已开始恢复；栈槽、
  fsbase、GS 基址、FPU 保存区未随迁移重新绑定。
- **后果**：栈 / 页表 / 浮点状态串核，触发 #GP / #DF；FPU 累加器漂移（历史 SB-08
  记录的同类风险）。
- **缓解手段**：迁移协议分阶段——旧核脱离（`running_on` 交接为 -1）→ 新核绑定
  本核栈槽 / FS / GS / FPU 保存区 → 再入目标 rq；迁移窗口内禁止抢占；每一步留
  诊断点；FPU 保存区槽位按核索引、不回绕复用。
- **验证方法**：（未来）迁移前后 PCB 栈 / 页表 / fsbase 与新核一致；并发浮点探针
  两侧结果不漂移；无跨核 FPU 状态复用记录。

### R8（P2）IPI 单槽丢失、中断上下文调度与应答汇聚超时

- **触发条件**：短时间多条 IPI 打到同一核，消息槽忙被拒收；`RESCHEDULE` 处理在
  中断上下文直接进入调度；应答汇聚等待超时；目标核已掉线仍被计入 expected。
- **后果**：消息丢失导致唤醒 / 刷新不到位；中断上下文重入调度造成死锁或栈错乱；
  汇聚超时拖长同步路径。
- **缓解手段**：槽忙计数 + 有限重试 / 退避；`RESCHEDULE` 只置 `need_resched` 类
  标志，在中断返回前走正常调度入口，不在 handler 内直接切换；应答汇聚按在线核
  位图逐核核对；超时显式报目标核号。
- **验证方法**：（未来）压力 IPI 下 dropped 可观测且有补偿；handler 无嵌套调度；
  汇聚超时路径报出核号；TLB_FLUSH / RESCHEDULE 两类消息各自计数对账。

### S1 per-CPU 化 current 与队列基础

- **入口条件**：HEAD 基线可启动；现有表级锁、IPI 通道、per-CPU syscall 槽在位
  （`user_process.c:189-191`、`smp.c:413-443`、`syscall64_simple.c:50`）。
- **改动面（计划）**：
  - `current_user_proc` 全局单值（`user_process.c:137,1901,2355-2356`）迁入
    per-CPU 区或随进程上下文携带；
  - uthread 全局游标与 slice 状态（`uthread64.c:41-42,47-50`）按 owner / 核拆分；

- **串口判据（未来验收）**：多核启动各核当前进程槽 / 内核栈槽互不相同；无 #SS /

- **回滚判据**：出现串栈、#DF、进程串槽或当前槽互相覆盖；退回全局单值与 BSP

### S2 AP 进入调度循环（最小闭环：只跑本核 idle）

- **入口条件**：S1 收口；每核专属 idle 已绑定（`process64_full.c:687-738`）；
  AP 启动协议、IDT / LAPIC / 定时器在位（`smp.c:195-269`）。
- **改动面（计划）**：
  - AP tick 路径确认只进入本核调度循环与 idle 回退；
  - 跨核窃取兜底（`process64_full.c:895-938`）在本阶段关闭或加独立开关；
  - AP 不接用户任务，不开放 clone 线程跨核；
  - 补 AP 侧 idle 进入 / 退出的诊断行。
- **串口判据（未来验收）**：AP 在线、本地定时器计数递增、无候选时回到本核 idle；
  不出现跨核候选被 AP 取走的记录；BSP 桌面主循环行为不回归；无异常向量记录。
- **回滚判据**：AP 取到别核任务导致桌面停摆或上下文损坏；关闭 AP 调度分支，
  AP 退回 `smp.c:270-272` 的 `hlt` 循环。

### S3 唤醒 IPI 与受控迁移

- **入口条件**：S2 稳定；`RESCHEDULE` 接收分发在位（`smp.c:387-394`）；TLB
  shootdown 在位（`vmm64.c:68-81`）；R2/R3 的计数原子化与归属收口先行。
- **改动面（计划）**：
  - wakeup 路径（`process64_full.c:1064-1077`）扩展跨核 `RESCHEDULE` 发送；
  - 落地 3.2 的迁移协议：摘源队 → 归属交接 → 栈 / FS / GS / FPU 重绑 → 入目标队；
  - 同进程 clone 线程默认同核亲和；
  - IPI 槽忙 / dropped / ack 计数纳入诊断输出。
- **串口判据（未来验收）**：跨核阻塞 → 唤醒在一个 tick 内响应；IPI 发送与 ack
  对账；无任务长期滞留 READY；迁移前后上下文与新核一致。
- **回滚判据**：IPI 汇聚超时、dropped 持续上涨、出现串核异常；关闭迁移与跨核
  唤醒，退回 S2 的本地队列 + 静态亲和。

### S4 负载均衡与受限工作窃取

- **入口条件**：S3 稳定；具备可观测的 per-核负载 / 等待时长统计。
- **改动面（计划）**：
  - per-CPU rq 间负载测量与忙闲判断；
  - 空闲核受限窃取：单次条目数上限、亲和 / 域优先；
  - 沿用现有优先级与域权重加权选择（`process64_full.c:815-848`）；
  - 饥饿观测与必要时的提权 / 再平衡。
- **串口判据（未来验收）**：任务在多核分布无重复、无丢失；长稳压测无饥饿；
  核间负载差在约定阈值内；无重复运行同一任务的记录。
- **回滚判据**：窃取导致任务重复运行或失队；关闭窃取，退回本地队列 + 静态亲和。

## 六、明确不做什么

### 6.1 本轮不做

- 不写实现代码、不改内核与构建、不起 QEMU / 真机验证；
- 不调整任何调度开关的取值；不承诺性能数字、核数扩展上限或长稳压测结论；
- 不改造 32 位遗留树与未编入 64 位镜像的旧 SMP 代码；
- 不引入新调度类（多级反馈队列、完全公平调度器等）；不改系统调用 ABI 与 clone /
  fork / wait 语义；
- 不把桌面内核上下文的共享状态下沉 ring3 或重画 owner 边界——该项属既有桌面
  隔离议题，不在 SB-25 调度方案内混做。

### 6.2 跳过 per-CPU 化直接上共享队列会踩的坑

若在 current 指针、内核栈槽、线程现场尚未 per-CPU 隔离时，直接让多核进入同一把
锁保护的共享队列：

1. **current 互相覆盖**：两核进内核后读 / 写同一个 `current_user_proc`，系统调用
   拿到别核进程的 fd、页表、凭据（现状全局单值见 `user_process.c:137`）；
2. **栈串栈**：syscall 内核栈槽、用户栈槽若仍共用单份，两核交替进系统调用会把
   对方栈帧写花，随机 #PF / #DF；
3. **线程现场串槽**：uthread 全局游标 `g_ut_cur` 被两核交替改写，保存现场写到
   别人槽、恢复时拿别人的 rip/rsp（`uthread64.c:41-42`）；
4. **中断上下文拿错进程**：定时器 / IPI 在错误的进程上下文里执行清理、kill 判断、
   凭据检查；
5. **故障不可归因**：没有 per-CPU 日志与核号标记，竞态随机复现，串口单通道交织
   输出，定位成本极高；
6. **锁瓶颈先行暴露**：共享队列单锁把所有核串行化，即使结构不被破坏，吞吐与延迟
   也会被锁竞争压住，且饥饿问题被调度复杂度掩盖。

结论：per-CPU 归属与栈 / 现场隔离是跨核调度的前置条件，顺序不能倒。

## 七、与现有台账的衔接

### 7.1 与 SEC-20 的关系

SEC-20 记录的是「用户线程是否为调度单元」：单核内 clone 线程可创建、可轮转、共享
地址空间与独立内核栈的功能层闭环（台账既有记录）。SB-25 接的是其剩余边界：

- 用户线程状态（`g_ut[]` / `g_ut_cur` / slice 计数）跨核隔离；
- 同一进程线程是否允许、在什么条件下跨核调度；
- 跨核唤醒、迁移与收尾（线程退出、地址空间保留）的竞态收口。

### 7.2 与 SEC-02 的关系

SEC-02 的 fork COW 路径与 SB-25 不冲突；clone 共享页表是 SEC-02 明确的边界项。
SB-25 范围内需要新增评估的是：共享页表在多核下的引用计数原子性、COW 拆页与
munmap 的跨核 TLB 刷新、地址空间释放前的他核运行确认（对应风险 R2）。

### 7.3 台账标注建议

- 在 `docs/status/OPEN_BUGS.md` 中为 SB-25 补独立条目，状态写「方案阶段（方案 /
  风险已出，实现未验证）」；
- 不改动 SEC-02 / SEC-20 及其他条目的既有结论；历史既有结论仍以其原条目与
  证据目录为准，本文不代为升级或关闭。
