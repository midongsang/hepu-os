# Hepu OS 存储/内存/安装体系规划（V0.13.45 规划稿）

## 一、现状核查（2026-10-23 实测）

### 1. 32 位与 64 位"是否共用一个地方"
| 资源 | 现状 | 结论 |
|------|------|------|
| 物理内存 | QEMU 256MB 同一块；64 位 pmm64 全盘接管（total_pages=memory_size/4096，vmm64 identity 映射 0-256MB）；32 位内核有独立分配器（lowmem_throttle/memory_optimizer/sys_mem） | **不共用**：双内核引导时二选一（Stage2 菜单），各自独立管理物理内存，**不同时运行** |
| 存储 | 镜像 = MBR + Stage2 + 64 内核(LBA2000，加载上限640KB) + 32 内核(LBA3400) + **单个 ext2 根分区**(LBA13000)；两内核挂载同一 ext2 | **共用** ✓：32/64 共享同一根分区文件系统（ext2_64 支持 partition_offset） |
| 缓存 | 内核堆 KHEAP 仅 256KB 静态数组；无页缓存/块缓存；无统一 IO 缓冲 | **未实现**：大程序加载即 OOM（OBS 需 5.9MB） |

**关键差距**：所谓"混合 32/64 位"目前是**引导时二选一**，不是**同系统内 32/64 程序共存**。程序级共存是兼容层职责（见兼容层规划：ELF32/ELF64 加载器统一）。

### 2. 分区现状
- 单 ext2 分区 = 系统 + 用户数据混在一起；无 /home、无数据分区、无 swap
- 用户三区制（系统/用户配置/自由）**完全未实现**

### 3. 安装现状
- 仅"镜像直接写盘"（Rufus DD / dd），无安装引导、无分区配置、无试用流程

## 二、三区制存储规划（核心）

### 分区布局（MBR/GPT，引导时由安装器创建）
| 分区 | 挂载点 | 内容 | 大小 |
|------|--------|------|------|
| 系统分区 | / | 内核、系统程序、系统库、驱动 | 固定下限（如 16GB，够系统+更新） |
| 用户配置分区 | /cfg（类 Windows C 盘但只存配置） | **仅软件/游戏配置文件**，不存系统、不装程序本体 | 用户自定 |
| 自由分区 | /data（类 D 盘） | 用户任意文件、游戏、软件安装本体 | 用户自定（剩余空间默认） |

**设计要点**
- 用户配置分区独立 = 防"系统分区膨胀拖累系统"；系统重装不影响配置分区
- 自由分区 = 软件/游戏安装目标 + 用户文件；通过"默认安装路径 /data/Programs、/data/Games"实现 Windows 语义
- 分区大小由用户决定：仅 U 盘安装模式下出现"分区配置页"

### 缓存/内存/存储提升项（P0 前置）
1. **KHEAP 扩容**：256KB → 8MB+，配套引导页表 + vmm 身份映射扩至 ≥64MB（Stage2 PD 与 multiboot_entry PD 32 大页；Stage2 改 32 项后 JMP> 卡死问题待查，回滚基线为 8MB/2MB）
2. **页缓存/块缓存**：ext2 读写加统一块缓存层（LRU，命中率统计），大文件 IO 不再逐扇区裸读
3. **swap/内存压力**：物理内存不足时按"缓存可回收→进程换出"降级（P2）
4. **统一存储 HAL**：IDE/AHCI/USB 走 storage_hal64 单入口（已有雏形），为安装器提供块设备列表

## 三、U 盘安装引导流程（规划）

```
镜像写入U盘 → U盘启动 → 进入试用模式（完整系统功能，可安装/运行软件验证）
  → 桌面弹出"为硬盘安装系统"入口
  → 安装引导（可选：立即安装 / 仅试用继续）
  → 磁盘选择页（列出 storage_hal 探测到的块设备，排除U盘自身）
  → 分区方案页：三区制（系统/用户配置/自由）+ 每区大小滑条（默认建议值）
  → 写盘页：创建分区表 → 格式化 ext2 → 拷贝系统文件 → 写入引导（MBR+Stage2+双内核）
  → 完成：弹出"重启并从硬盘启动"；U盘可拔出
```

**交付路径**：内核侧新增 `installer64` 应用（hs_apps 注册"安装系统"入口）+ `partition_tool`（MBR 分区表读写，已有 MBR 写入代码可复用 make_single_img64.sh 的 python 逻辑）+ 拷贝器（ext2 批量写，复用 obs_install_test.sh 的 debugfs 思路的内核版）。

## 四、整合后总优先级（P0-P4）

**P0（系统稳定 + 安装体系地基）**
- 兼容层：KHEAP 8MB + 页表/映射配套（当前硬卡点）
- 存储：MBR 分区表读写工具（用户态，为三区制打底）、ext2 块缓存
- 安装：分区配置 UI（三区制）+ "为硬盘安装系统"引导流（试用→安装→重启）
- 维持：64 位 syscall 链路回归、图形基线回归

**P1（内存/存储支撑）**
- swap/内存压力管理、统一块缓存落地到全部存储驱动
- 系统分区/用户配置分区自动挂载（/cfg、/data 开机挂载表）
- 兼容层：动态链接器 ld-linux（P1）、POSIX syscall 层（P1，OBS 级软件前置）

**P2（三区制完善）**
- 用户配置分区重装保留、系统更新不动 /cfg、/data
- "默认安装到 /data"的软件安装器（deb 解包→部署→注册，复用 OBS 安装实测）
- 大文件 IO 性能（缓存命中率、读写吞吐）

**P3（远期）**
- OBS 等 Qt/GL 应用（glibc2.38 + Qt6 + FFmpeg 移植）
- 32/64 程序同系统共存（双加载器统一调度）

## 五、验收标准
- P0：U 盘启动可试用；安装引导可配置三区大小并写盘；重启从硬盘启动且三区挂载正确
- 存储：大文件（≥50MB）读写不逐扇区裸读（缓存命中日志可证）；KHEAP ≥8MB 且 OBS 主程序加载过 OOM
- 回归：64 位 hello 链路、图形桌面基线全绿
