# 赫普OS 中文输入法落地计划（2026-11-28）

## 0. 结论

不能只把 32 位的 `kernel/apps/ime.c` 编进 64 位内核。当前缺的不是一个拼音表，而是三层能力：

1. **能显示**：现有 IME 词库有 1,985 个不重复汉字，64 位桌面字体只覆盖其中 559 个；直接接上会出现 72% 候选字空白。
2. **能编辑**：终端和编辑器只接受单字节 ASCII，退格按字节删；中文 UTF-8 插入后，退格、光标和列宽都会坏。
3. **能上屏**：桌面没有“组合中字符串 / 候选浮层 / 提交文本”的输入契约，Esc 还被全局抢去开 shell。

因此按 **先字库、再文本缓冲、再 IME 核心与桌面接线、最后候选体验和词库扩展** 的顺序做。第一版承诺“简体拼音、**EN/ZH 可切换**、终端与编辑器可输入、密码框不走 IME”，不承诺五笔、手写、语音或完整中文 UI。

## 1. 现状证据

### 1.1 已有 IME 核心只服务 32 位移动模块

- `kernel/apps/ime.c`（330 行）实现拼音前缀匹配、9 候选/页、词组与简拼；API 在 `kernel/include/ime.h`：`ime_input()`、`ime_candidate_get()`、`ime_commit_first()`、`ime_page_next()`、`ime_bump()`。
- 数据在 `kernel/apps/ime_data.c`、`ime_data_table.c`，去重后 **1,985 个汉字**。
- 目前只有 32 位 `mobile_contacts.c`、`mobile_sms.c` 调用；`kernel/arch/x86_64/Makefile` 没有编译 `ime.c`。
- `ime.c` 依赖 32 位 `ide_ext2_read_file()` / `/data/ime/freq.txt` 做词频持久化，不能直接链接进 64 位桌面。

### 1.2 64 位桌面没有文本输入契约

- 键盘入口：`hsinput.c:hs_input_poll()` → `hpdesk_handle_key(int key)`。
- 终端 `t_handle_key()` 只收 `key >= 32 && key < 127`；编辑器 `ed_handle_key()` 只收 `key >= 32 && key <= 126`；登录/账户密码同样只收 ASCII。
- `hs_input_poll()` 在普通键分发前就把 `Esc` 送给 `shell64_run()`，输入法不能用 Esc 取消组合。
- 没有候选层、组合字符串、光标位置回传，也没有“提交一段 UTF-8 到当前焦点控件”的接口。

### 1.3 字库缺口是硬约束

| 项 | 数值 |
|---|---:|
| 现有 IME 去重汉字 | 1,985 |
| 64 位 `NotoSansCJK-Subset.ttf` 覆盖 | 559 |
| 缺字 | 1,426（约 72%） |
| 32 位 `hepu_cjk_big` 16×16 点阵覆盖 | 1,971 |
| 点阵仍缺 | 14 个生僻字（呃、尬、岑、愣、昵、楠、欻、涮、瞟、耨、踹、辍、迥、鞥） |

结论：**候选字能显示，是输入法可用的前置条件，不是视觉收尾。** 现有 3,775 字 16×16 点阵（`kernel/include/font_cjk_big.h`，约 136 KB 二进制）已覆盖 99.3% 的 IME 词库，是最小代价的兜底方案。

## 2. 目标架构

```text
键盘
  │
  ▼
hsinput.c  ── Ctrl+Space / Esc 过滤 ──►  hs_ime.c（桌面适配层）
                                          │
                    ┌─────────────────────┼─────────────────────┐
                    ▼                     ▼                     ▼
              ime_core.c            候选浮层渲染          文本目标接口
          （共享 32/64）          （hpdesk overlay）    hs_apps_text_*
                    │                     │                     │
                    ▼                     ▼                     ▼
              ime_dict.c            gfx64 字体回退         终端 / 编辑器
          （拼音表、词组）       TTF → 16px 点阵兜底      UTF-8 缓冲与光标
```

### 2.1 共享 IME 核心

把 `kernel/apps/ime.c` 搬到 `kernel/shared/ime/`，数据表同迁：

- `ime_core.c`：保留现有 API 与 9 候选/页、8 字母上限，先不改算法。
- `ime_storage.h`：把 `ide_ext2_read_file` / `ide_ext2_writefile` 抽成 `ime_storage_load()` / `ime_storage_save()`。
  - 32 位适配器继续走 `ide_ext2`，移动联系人/短信行为不变。
  - 64 位第一版可先只做会话内词频；M2 再接 `ext2_64` / VFS，不把存储依赖塞进核心。
- 32 位 Makefile 增加共享目录 include；64 位 Makefile 增加 `ime_core.c` 与数据表。两边共用同一份词库，避免两份拼音表漂移。

### 2.2 桌面适配层

新增 `kernel/arch/x86_64/hs_ime.c/.h`：

- 状态：`mode`（`EN` / `ZH`）、`composing`（拼音非空）、候选页。
- **中英文双模**是产品要求，不是附属开关：
  - `EN` 模式：所有可打印 ASCII 原样下发，不组词、不出候选；`t`、`l` 等应用/快捷键行为与没装输入法时完全一致。
  - `ZH` 模式：有文本焦点时，`a-z` 进入拼音组合；候选上屏后才产生 UTF-8，不会把拼音字母漏进正文。
  - 切换时若正在组合，**丢弃当前拼音组合并清空候选**，不把半截拼音写进文本；状态徽标同步变化。
  - 模式持久化到 `sys.ime_mode=zh|en`，重启后恢复；默认 `en`，避免首次登录/命令行被意外拦截。
- 状态徽标：候选条左侧常驻 `中` / `EN`；切换时发 2 秒通知。M2 再把徽标接到顶栏，暂不挤压现有 5 个状态图标。
- `hs_ime_filter_key(key, mod)`：在 `hs_input_poll()` 里、`hs_handle_shortcut()` 与 Esc 分支之前调用，返回 1 表示已消费。
- 键位第一版：
  - `Ctrl+Space`：在 `EN` / `ZH` 之间切换；消费，不下发应用。
  - `a-z`：仅 `ZH` 组合中追加拼音；`Backspace`：删一个拼音字母。
  - `1-9`：选当前页候选；`0`：下一页；`Space/Enter`：上屏首候选。
  - `Esc`：取消组合并消费，**不打开 shell**；无组合时照旧交给 shell。
  - 未组合时，字母是否进入 IME 取决于“`ZH` 模式 + 当前有文本焦点”；任一不满足就不抢应用快捷键。
- `hs_ime_render()`：画候选条/浮层；第一版固定在 Dock 上方居中，M2 起跟随光标。
- `hs_ime_commit()`：调用 `ime_commit_first()`，把 UTF-8 交给当前文本目标，并 `ime_bump()` 记频率。

### 2.3 文本目标接口

在 `hs_apps.c` 增加最小契约，不让 IME 直接摸终端/编辑器内部：

```c
int  hs_apps_text_focus(void);                 /* 当前是否有可输入文本焦点 */
int  hs_apps_text_ime_allowed(void);           /* 密码框返回 0 */
int  hs_apps_text_insert_utf8(const char *s);  /* 提交候选 */
int  hs_apps_text_backspace_utf8(void);
int  hs_apps_text_caret(int *x, int *y);       /* M2 候选跟随光标 */
```

第一版接入：

- **终端**：`t_insert_utf8()` 追加到输入缓冲；`t_backspace_utf8()` 删一个完整码点。命令解析仍按字节，中文参数/文件名可原样传递。
- **编辑器**：新增 `ed_insert_utf8()`、`ed_backspace_utf8()`、按码点移动光标；渲染列宽按“ASCII 1 列、CJK 2 列、组合字符 0 列”计算。
- **密码框 / 登录**：`hs_apps_text_ime_allowed()` 返回 0，强制 ASCII，不允许候选层出现。
- 第一版不覆盖启动器搜索、设置搜索等没有文本焦点的场景。

### 2.4 UTF-8 文本缓冲

新增 `hs_text_utf8.c/.h`，只做四件事：

- `utf8_next()` / `utf8_prev()`：按码点前进/后退；
- `utf8_cols()`：显示列宽；
- `text_insert_utf8()`：在字节缓冲中插入；
- `text_backspace_utf8()`：删光标前一个完整码点。

终端和编辑器都走这套，禁止各写一份“按字节退格”。这是中文输入不出现乱码/半个字的关键。

### 2.5 字体回退

在 `gfx64_put_ttf()` 的 CJK 分支增加回退：

1. 先走现有 TTF；有字形就用 TTF（小字号质量最好）。
2. TTF 返回缺字时，查 `hepu_cjk_big` 的 16×16 点阵；按 `gfx_ttf_size` 缩放绘制，返回方形 advance。
3. `gfx64_measure_text()` 使用同一回退宽度，避免候选条/编辑器测量与绘制不一致。
4. 第一版把 3,775 字点阵编入 64 位内核（约 +136 KB rodata）；如果启动镜像超限，再打包成 `/fonts/cjk16.bin`，启动后读入堆，内核不留这份数据。
5. 大字号（天气卡 36px）仍可能看出点阵感；M4 再评估外置完整 CJK 轮廓字体，不阻塞输入法。

> 不做“只保留字体里已有的 559 字”这种假输入法：候选看起来有，选中后是空白，等于没做。

## 3. 分阶段实施

### M0：字库兜底 + UTF-8 文本缓冲（P0，先做）

交付：

- `gfx64_put_ttf()` 缺字回退到 16px 点阵；`gfx64_measure_text()` 同步。
- `hs_text_utf8.c/.h` 与 host 单测：`你`、`好`、`中国` 的插入/退格/列宽。
- `tools/check_ime_glyphs.py`：扫描 IME 两张数据表与字体/点阵表，输出缺字清单；验收要求 0 缺字（14 个生僻字补点阵或从词库显式剔除，不能静默跳过）。
- 记录 64 位内核体积变化与 QEMU 启动是否仍通过。

验收：

- 输入法词库每个汉字都能在 16px / 24px 下画出非空字形。
- 终端里手动塞入 `你好` 的 UTF-8 字节，退格一次删掉整个“好”，不留下半个字节。
- 64 位构建、32 位构建、host tests 全过；无 IME 的桌面基线截图不变。

### M1：共享 IME 核心 + 终端输入（P0）

交付：

- `kernel/shared/ime/` 迁移；32 位移动端编译与行为不变；64 位 Makefile 接入。
- `hs_ime.c/.h`：`EN/ZH` 双模、`Ctrl+Space` 切换、拼音组合、9 候选/页、0 翻页、空格/回车上屏、Esc 取消。
- `hsinput.c` 过滤：IME 组合中的 Esc 不再触发 `shell64_run()`；`Ctrl+Space` 不再穿透到应用。
- 终端 `t_insert_utf8()` / `t_backspace_utf8()` 接入；候选条固定在 Dock 上方。
- 状态提示：候选条左侧常驻 `中` / `EN`，切换时发一条 2 秒通知；暂不动顶栏 5 个状态图标。
- 模式切换时丢弃未上屏的拼音组合，不把拼音字母漏进终端正文。

验收（QEMU 合成环境，不写“真机已验证”）：

- 终端输入 `nihao` → 候选含“你好” → 空格上屏，终端显示 `你好`。
- `zhongguo` → 上屏 `中国`；`0` 能翻到下一页；`Backspace` 逐字母回退；`Esc` 取消且不弹 shell。
- 切到 `EN` 后输入 `nihao`，终端原样显示 `nihao`，不弹候选；再切回 `ZH` 后恢复组词。
- 组合中按 `Ctrl+Space` 切到 `EN`，拼音组合消失，终端正文不新增字符。
- `Ctrl+Space` 关闭后，`t`、`l` 等单键恢复原有快捷键行为。
- 32 位冒烟 `smoke32.sh` 不回归；host tests 通过。

### M2：编辑器 + 候选浮层 + 词频持久化（P1）

交付：

- 编辑器 UTF-8 插入、退格、光标左右移动、保存/重开；中文按 2 列宽渲染。
- 候选浮层从固定条升级为“跟随文本光标”：`hs_apps_text_caret()` 返回光标屏幕坐标，浮层优先显示在光标上方，越界翻到下方。
- 鼠标点选候选（第一版键盘 1-9 仍保留）。
- 64 位 `ime_storage` 接 `ext2_64` / VFS，词频写入 `/data/ime/freq.txt`；若镜像没有独立 `/data` 分区，则在根文件系统创建 `/data/ime` 后写入。失败时只保留会话内词频，不阻塞输入。
- `sys.ime_mode=zh|en` 记住上次模式；默认英文输入，`Ctrl+Space` 切换。

验收：

- 编辑器输入 `nihao` 上屏 `你好`，保存为文件，重启后 `cat` 能读回同一串 UTF-8。
- 光标在行中/行尾时，候选浮层不遮挡光标所在行；窗口靠右/靠下时不超出屏幕。
- 词频文件写入后重启仍生效；拔掉/只读盘时输入法仍可用。

### M3：词库扩展与输入体验（P1/P2）——已完成

交付：

- 新增 `tools/ime-data/gb2312-level1-pinyin.txt`（GB2312 一级 3,755 字，86,908B）和生成器 `tools/gen_ime_data.py`；读音取自 `mozillazg/pinyin-data` v0.16.0（MIT），许可证与来源说明随数据入库。生成表 `kernel/shared/ime/ime_data_table.c` 为 407 个拼音组、3,769 个去重汉字、5,227 个“字-读音”出现、28,156B；保留原有 14 个表外生僻字，最大组 `yi` 82 字。
- 候选缓存上限扩到 `IME_CAND_MAX=99`，默认每页 9 个；`yi` 组显示 11 页。
- 候选条显示拼音分段（`nihao → ni hao`、`zhongguo → zhong guo`），保留词频排序、词组优先和简拼；组合中 `0x92` 左键上一页、`0x93` 右键下一页。
- Settings 64 位导航新增 Input 页，三行真实控件：Mode（English/Chinese）、Candidates/page（9→7→5 循环）、Remember frequency（On/Off）。点击分别调用 `hs_ime_set_mode()`、`hs_ime_set_page_size()`、`hs_ime_set_freq_enabled()`，并写 `sys.ime_mode`、`sys.ime_candidates`、`sys.ime_freq` 注册表，不是假控件。32 位 Settings 仍为 7 项导航。

验收结果：

- 字库检查 3,769/3,769 覆盖，无空白候选；`font_cjk_big` 3,789 码点。
- 主机测试 22/22，`ime_core` 断言 `yi` 99 候选/11 页、5/页时 20 页、9/页恢复 11 页、词频开关关闭后不记录不落盘、`nh → 你好` 简拼保留；`ime_firstpage` 实测常用 500 字首屏 472/500（94.4%）、100 词组 100/100。
- `ime_freq_off_probe.sh` 三次启动验证：Off 后输入 `zhongguo` 选 1（中国），`/data/ime/freq.txt` 与基线逐字节一致（仍为 `鞥 1`），第三次启动 Input 页仍为 Off。
- QEMU 编辑器：`nihao` 候选条 `ni hao`，数字 1 上屏 `你好`；`yi` 1/11 → 右键 2/11 → 左键 1/11；`zhongguo` 候选条 `zhong guo`，数字 1 上屏 `你好中国`。
- QEMU 终端：`echo ` + `nihao` + `1` + 回车输出 `你好`。
- Settings QEMU：Mode 点击后 `Chinese (ZH)`，Candidates/page 点击后 `7`，Remember frequency 点击后 `Off`；候选数与词频的新一轮跨重启探针读回 `sys.ime_candidates=7`、`sys.ime_freq=off`，第二次启动 Input 页显示 7/Off。
- `sys.ime_mode=zh` 与 `/data/ime/freq.txt`（`你好 1`、`鞥 1`）跨重启读回；编辑器首行中文保存/读回。
- 构建：`kernel64.bin=1,263,312B`、`kernel32.bin=3,899,021B`、`image=268,435,456B`。100% 九态视觉 9/9 PASS（02 mean=0.085，其余 0.042/0.000），32 位 smoke PASS。

边界：

- 常用 500 字首屏 472/500（94.4%），28 个未进首屏的字全部仍在词表/字库中，原因是 `di`/`dian`/`gu` 等读音组候选超过 9 个；100 词组首屏 100/100。明细见 `docs/status/ime-m3-2026-11-28/FIRSTPAGE.md`。
- 启动时间没有独立量化，只记录内核/镜像体积；不能据此声称“启动时间已验证”。
- Settings 持久化探针使用 QEMU 复制镜像 + writethrough，不是实机；首轮 M3 持久化探针曾落到 OOBE 首启页，未计入证据，清理夹具后复跑通过。
- 真实 P3 `/data`、只读盘/无 `/data` 降级、候选条在窗口右侧/底部边界的鼠标命中仍未验证。

### M4：中文 UI 与字体升级（独立轨道，不计入输入法验收）

输入法只解决“能打字”，不等于系统全中文。此阶段单独做：

- `l10n64` 从 16 个字符串扩到桌面菜单、控制中心、天气卡、应用名、设置项；
- 天气现象中文映射补 `晴/多云/阴/雨/雪` 等；日期用“星期X”而非“周X”；
- 评估外置完整 CJK 轮廓字体，解决 24px 以上点阵感；保留 16px 点阵兜底；
- 语言切换后不重启即可刷新已开窗口（或明确提示重启）。

验收：

- `lang set zh` 后桌面主要可见文案为中文，英文残留有清单，不假装 100%。
- 中文字体在 12/16/24/36px 四档截图可读；无空白字。

## 5. 验收矩阵

## 6. 风险与边界

1. **字库体积**：+136 KB 点阵可能把 64 位镜像推高；先实测启动，若超限改为 `/fonts/cjk16.bin` 外置。不得用“缺字跳过”换体积。
2. **Esc 冲突**：当前 Esc 是全局 shell 入口，必须先让 IME 过滤；只在组合中拦截，避免改掉原有行为。
3. **UTF-8 光标**：编辑器按字节退格会留下半个汉字；M0 不完成就不接 M1 编辑器。
4. **候选浮层遮挡**：第一版固定 Dock 上方可接受；M2 跟随光标必须做边界翻转，不能盖住输入行。
5. **32/64 分叉**：共享核心必须同时编进 32 位移动端；每次改词库跑 32 位 smoke，不接受“64 位单独一份表”。
6. **词库许可**：扩到 3,755 字前先核词库/拼音数据许可证，生成脚本入库，不把来源不明的表塞进内核。
7. **范围**：第一版不做五笔、双拼、手写、语音、云联想、完整中文 UI；这些不阻塞“能输入中文”。
