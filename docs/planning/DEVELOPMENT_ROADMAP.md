# 赫普OS 软件开发路线图 (Development Roadmap)

> 版本：V1.0  
> 日期：2026-09-21  
> 核心理念：系统归人，数据归己，自由可控，极致纯净  
> 战略原则：先兼容再创新、开发者体验优先、渐进式完善、社区驱动、向后兼容

## 二、六大发展方向详细规划

### 方向一：完善核心系统API

#### 1.1 图形子系统（最优先 P0）

**目标**：从"能显示"到"能开发美观应用"

**阶段1：基础绘图API完善（1-2个月）**
- ✅ 点、线、矩形（已有）
- ⬜ 圆形/椭圆绘制
- ⬜ 多边形填充
- ⬜ 位图绘制（BMP/PNG解码）
- ⬜ 双缓冲（避免闪烁）
- ⬜ 透明色/Alpha混合

**阶段2：窗口管理系统增强（2-3个月）**
- ✅ 窗口创建/移动（已有基础）
- ⬜ 窗口缩放（拖拽边框）
- ⬜ 最小化/最大化/还原
- ⬜ 窗口关闭按钮
- ⬜ Z轴顺序管理（点击置顶）
- ⬜ 窗口装饰（标题栏/边框/按钮）
- ⬜ 窗口拖拽时的半透明预览

**阶段3：UI组件库（3-4个月）**
- ⬜ Button（按钮：普通/按下/禁用状态）
- ⬜ Label（静态文本）
- ⬜ TextInput（单行输入框：光标/选择/复制粘贴）
- ⬜ TextArea（多行文本编辑）
- ⬜ ListBox（列表框：滚动/选择）
- ⬜ ComboBox（下拉框）
- ⬜ CheckBox/RadioButton（复选/单选）
- ⬜ Menu（菜单栏/右键菜单）
- ⬜ Dialog（对话框：确定/取消）
- ⬜ ProgressBar（进度条）
- ⬜ Slider（滑块）
- ⬜ TabControl（标签页）
- ⬜ ScrollBar（滚动条）

**阶段4：字体渲染（2-3个月，可并行）**
- ⬜ TrueType 字体解析（freetype 移植或自研）
- ⬜ 抗锯齿渲染
- ⬜ 字体缓存（glyph cache）
- ⬜ 多语言字库（中文/日文/韩文/阿拉伯文）
- ⬜ 字体大小/粗体/斜体
- ⬜ 文本布局（换行/对齐/行间距）

#### 1.2 网络协议栈（P1）

**目标**：从"能通信"到"标准易用"

**阶段1：Socket API 标准化（1-2个月）**
- ⬜ BSD Socket 接口（socket/bind/listen/accept/connect/send/recv/close）
- ⬜ select/poll 多路复用
- ⬜ getsockopt/setsockopt
- ⬜ gethostbyname/getaddrinfo
- ⬜ inet_pton/inet_ntop

**阶段2：安全通信（2个月）**
- ⬜ TLS/SSL 支持（mbedtls 移植）
- ⬜ HTTPS 客户端
- ⬜ 证书验证
- ⬜ 加密API（AES/RSA/SHA/HMAC）

**阶段3：高级协议（2-3个月）**
- ⬜ WebSocket 客户端/服务端
- ⬜ FTP 客户端
- ⬜ SMTP/POP3 邮件
- ⬜ MQTT 物联网协议
- ⬜ gRPC/REST 框架

#### 1.3 输入系统（P1）

**阶段1：统一输入事件（1个月）**
- ✅ 键盘/鼠标/触摸基础驱动（已有）
- ⬜ 统一事件结构体（type/time/device/data）
- ⬜ 事件队列（生产者/消费者模型）
- ⬜ 事件过滤/钩子机制

**阶段2：输入法框架（2个月）**
- ⬜ 输入法接口（activate/deactivate/process_key/commit_string）
- ⬜ 拼音输入法（基础）
- ⬜ 候选词窗口
- ⬜ 用户词库

**阶段3：手势识别（2个月，触摸屏优先）**
- ⬜ 点击/双击
- ⬜ 长按
- ⬜ 滑动（方向/速度）
- ⬜ 双指缩放
- ⬜ 手势事件分发

#### 1.4 文件系统（P2）

**阶段1：VFS完善（1个月）**
- ✅ ext2/ext4/exfat（已有基础）
- ⬜ FAT32 完整支持
- ⬜ ISO9660（CD-ROM）
- ⬜ 目录操作完整API（mkdir/rmdir/readdir/rename）
- ⬜ 文件权限（chmod/chown）
- ⬜ 软链接/硬链接

**阶段2：高级特性（2个月）**
- ⬜ 文件锁（fcntl/flock）
- ⬜ 内存映射文件（mmap）
- ⬜ 异步IO
- ⬜ 磁盘配额
- ⬜ 日志文件系统（journaling）

## 四、核心理念落地建议

### 4.1 先兼容，再创新

- **短期**：优先实现POSIX标准接口，方便移植Linux现有应用和库
- **中期**：在兼容基础上，推出赫普OS特色API（如安全/隐私/移动适配）
- **长期**：形成赫普OS独特的技术栈和应用生态

### 4.2 开发者体验优先

- **文档先行**：每个功能上线前，先写好API文档和示例
- **工具链完善**：编译器/调试器/构建工具/包管理器，一样不能少
- **错误信息友好**：编译错误/运行时错误/系统错误，都要清晰可读
- **一键运行**：从编写到运行，尽可能少的步骤

### 4.3 渐进式完善

- **最小可用**：先做最小可用系统（能编译/运行/调试基础应用）
- **快速迭代**：每个版本都有明确的改进，小步快跑
- **不追求大而全**：先把核心功能做扎实，再扩展边缘功能
- **质量优先**：每个功能都要经过测试，不要半成品上线

### 4.4 社区驱动

- **开放贡献**：代码/文档/示例/应用，都欢迎贡献
- **贡献指南**：清晰的贡献流程和代码规范
- **社区治理**：透明的决策过程，社区投票
- **激励机制**：贡献者认可/荣誉/奖励

### 4.5 向后兼容

- **API稳定**：核心API一旦发布，不轻易破坏性变更
- **版本管理**：语义化版本号（主版本.次版本.修订号）
- **弃用周期**：废弃API至少保留2个大版本，给开发者迁移时间
- **兼容性测试**：每个版本都要测试旧应用是否能正常运行
