# 双视图交互方案（VIEW_SWITCH）

> 定位：把 [DESIGN](../architecture/DESIGN.md) 0.14 的架构约束落成 UI/UX 执行方案。
> 权限模型、能力令牌与撤销协议以 DESIGN 0.11 为准；无头与启动 profile 以 DESIGN 0.13 为准。
> 本文只整理视图、入口、依赖与阶段，不重复内核契约。

## 一、结论先行

1. **一套数据源、一套能力，两种视图。** 视图只决定展示与入口，不决定授权。
2. 开发者模式是**会话级调试能力**：图形桌面与串口各持一份，互不继承；全局
   `hepu_dev_mode` 只能作为过渡期的界面缓存。
3. **视图切换不重启系统；“无头/桌面/游戏”启动 profile 切换需重启。** 两者不能混为一谈。
4. 普通视图以**应用组**为单位；内核不定义“应用”，由用户态 monitor 聚合。
5. 后端未就绪前不新增图形标签页；先用文本视图验证 `stat` 快照，再谈界面。

## 二、两层边界

| 维度 | 视图模式 | 启动 profile |
|------|----------|--------------|
| 例子 | 普通视图 / 开发者视图 | `headless` / `desktop` / `game` |
| 生效 | 会话内切换 | 启动期冻结 |
| 是否重启 | 不重启 | 需重启 |
| 独立范围 | 每个会话独立 | 整机一份 |
| 授权 | 调试会话能力 | 服务与显示集合 |
| 数据源 | monitor 快照 | 同一套内核能力 |

## 三、普通用户视图

标签页：【应用】【性能总览】【权限】。

| 区域 | 内容 | 数据来源 | 现状 |
|------|------|----------|------|
| 应用卡片 | 图标、名称、类型标签、CPU/内存/IO、终止、限制资源、权限设置 | monitor 应用组 | 未具备 |
| 性能总览 | CPU/内存/磁盘/网络/GPU 曲线；办公/游戏/安静模板 | monitor + QoS 服务 | 曲线未具备；模板为占位文案 |
| 权限管理 | 应用列表；人话权限；允许/拒绝/撤销 | 权限 broker 元数据 | 未具备 |

普通视图**不展示**：PID、线程列表、阻塞原因、句柄、内核线程、驱动条目、syscall 统计。

约束：

- 应用组按包身份、域集合、进程集合聚合；兼容层内部线程与子进程折叠；
- 权限只写“访问文件、摄像头、剪贴板、系统 AI、网络”等资源类，不写 fd/mmap/DMA；
- 资源提醒只在持续占用时出现，最多两个动作；崩溃只提示“应用无响应”，不投内核栈；
- 跨域剪贴板与文件选择默认拒绝，用户确认后才放行。

## 四、开发者视图

普通功能全部保留，新增标签页与操作。

| 标签 | 内容 | 前置后端 | 现状 |
|------|------|----------|------|
| 隔离域树 | 域 ID、类型、QoS 标签、配额、子进程、域操作 | 域表与域 ID | 只有 `env_type` 分组，无域对象 |
| 进程/线程 | PID/TID/父 PID/域/状态/阻塞原因；暂停、终止、追踪、转储 | `stat` 快照 + 阻塞原因 | 快照已建立；阻塞原因未具备 |
| 句柄与文件 | fd、socket、映射文件、共享内存 | 跨域句柄查询 | 未具备 |
| 驱动 | 驱动列表、所属线程、内存占用；只看统计 | 驱动统计接口 | 只有数量与描述 |
| 实时追踪 | syscall、进程事件、兼容翻译日志；按 PID/域过滤 | 事件流与环形缓冲 | 未具备 |
| 崩溃转储 | panic 日志、栈、进程快照打包 | core dump 与日志服务 | 未具备 |

Shell 与图形必须同源：图形选中对象后可在 Shell 继续追踪；无头与桌面共用同一套命令。
当前 64 位 Shell 在核内用 C 实现，用户态 Shell 是前置条件；结构化 Shell 只能作为用户态
前端，不作为内核依赖。

## 五、共享机制

| 组件 | 职责 | 不能做 |
|------|------|--------|
| monitor 服务 | 唯一快照、应用组聚合、脱敏、限流 | 直读内核结构、伪造数据 |
| 权限 broker | 资源类、风险等级、作用域、可撤销性 | 让界面自造权限文案 |
| 日志服务 | 用户/应用/兼容翻译/内核四级；按域过滤 | 把内核日志默认推给普通用户 |
| hepua | 两套解释风格；上下文为一次性只读快照；工具走 broker | 自动读取追踪数据、直接执行动作 |
| 文件管理器 | 普通视图按目录过滤，开发者视图全可见 | 用目录可见性代替能力裁决 |

## 六、安全围栏

- 内核核心线程、基础存储与中断驱动：禁止终止、禁止附加写调试；
- 高危操作（杀核心服务、附加调试内核内存、改内存保护、关闭隔离策略）二次确认并审计；
- `hepu.unsafe_debug=1` 是独立能力，仅本地开发镜像可用，不随开发者模式自动获得；
- 关闭开发者模式即撤销：追踪停止、dump 句柄失效、高级入口隐藏；
- 多会话独立：图形普通模式下，串口会话可单独持有调试能力。

## 七、阶段与依赖

| 阶段 | 内容 | 前置 | 验收 |
|------|------|------|------|
| P0 | 文本开发者视图；`ps` 双视图已迁移快照 | `process64_snapshot` | 普通/开发者视图读同一份数据，无越界与影子结构 |
| P1 | monitor 快照服务、应用组、普通视图文本版 | 域/进程映射、包身份 | 应用卡片可追溯到域与进程 |
| P2 | 会话调试能力、域树、进程/线程、基础追踪 | 域表、事件流、能力 broker | 关闭后追踪立即停止；未认证不可开启 |
| P3 | 句柄、驱动、转储、日志服务、权限面板 | 句柄表、日志分级、权限元数据 | 标签页数据与实际能力一致 |
| P4 | 图形双视图、文件管理器、通知、跨域剪贴板、hepua 两模式 | 用户态 Shell、剪贴板服务、AI 服务 | 普通视图不泄露内核信息；AI 上下文受控 |

## 八、降级与不做

**降级为目标的表述**

- “Domain ID / linux-compat-0 下挂具体应用”：当前只有 `env_type` 分组，域对象与域树未具备；
- “句柄与打开文件”：跨域句柄查询未具备；
- “驱动所属内核线程、非分页内存”：驱动统计字段未具备；
- “复制文件自动格式适配”：跨兼容层格式适配不属于视图层；
- “AI 自动获取追踪上下文”：必须由拥有者域生成一次性只读快照；
- “完整 Nushell”：用户态 Shell 尚未具备，不能作为内核依赖。

**明确不做**

- 不做两套独立桌面或两套割裂系统；
- 不把开发者模式当 root，不因调试放开内存保护与核心域；
- 不让界面直读内核 `process_t` 或暴露内核指针；
- 不在普通视图使用硬编码、占位或推测数据；
- 不用全局布尔量作为授权边界；
- 不声称 trace、dump、热重载或 AI 诊断已可用。
