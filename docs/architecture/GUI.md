# 赫普OS 图形化界面（GUI）设计文档 V2.35

> 状态：规划中 · 适用系统版本 0.54.6 · 双模式架构总纲
> 项目定位：**手机操作系统**。本文档为 GUI 设计的统一纲领，明确「桌面模式=开发验证平台」「手机模式=产品目标形态」两条腿并行的架构。

---

## 0. 项目定位与方向（总纲）

赫普OS 是**手机操作系统**，但当前真实硬件环境（QEMU、PC 真机）只有 **VGA 图形 + PS/2 键盘鼠标，无触摸屏**。因此 GUI 采用**双模式架构**：

```
                        ┌─────────────────────────────┐
                        │      应用层 (共用)           │
                        │  hello/terminal/files/notes │
                        └─────────────┬───────────────┘
                          ┌───────────┴───────────┐
                ┌─────────▼─────────┐   ┌─────────▼─────────┐
                │  桌面模式 (现役)    │   │  手机模式 (目标)    │
                │  DE-based 窗口系统  │   │  Touch-based UI   │
                │  开发验证驾驶舱      │   │  产品形态          │
                └─────────┬─────────┘   └─────────┬─────────┘
                          └───────────┬───────────┘
                ┌─────────────────────▼─────────────────────┐
                │      共享平台层 (同一套)                     │
                │  图形抽象 / 输入抽象 / 主题 / 控件基元        │
                │  内核 / 驱动 / 文件系统 / 进程调度           │
                └────────────────────────────────────────────┘
```

**两条腿分工**：
- **桌面模式**：现在就在跑，用鼠标键盘窗口系统，为开发/调试/验证内核、驱动、文件系统、应用逻辑服务——是**开发驾驶舱**，永久保留。
- **手机模式**：目标产品形态——竖屏、状态栏、全屏应用、图标网格、触控手势、虚拟键盘。依赖 VBE 高分辨率与触屏驱动就绪后启动（见阶段 D/E）。

**共用一切**：两个模式共享内核、驱动、图形抽象、主题体系、控件基元、应用框架——差异只在**交互范式与布局容器**。

## 1. 现状盘点（V2.33 基线）

| 模块 | 文件 | 现有能力 | 缺口 |
|---|---|---|---|
| 图形驱动 | `vga_gfx.c` | mode 13h 320x200x256、双缓冲(flip/vsync)、点/线/矩形/填充/字符/字符串、VGA 调色板 | 分辨率低、无 VBE、字符仅 8x8 英文、无半透明 |
| 窗口管理器(桌面) | `wm.c` (624行) | 窗口创建/销毁/拖动/置顶/最小化、焦点、任务栏、键盘导航、箭头光标、桌面图标、时钟 | 控件仅 3 种、无滚动/列表/复选框、颜色硬编码、无主题、无模态对话框 |
| 桌面 | `desktop.c` | App Launcher、文件浏览窗口、图标启动 | 无壁纸、无右键菜单、无选中态 |
| 应用 | hello/terminal/about/files/settings/browser/notes | 7 个基础应用 | 无统一应用框架、settings/browser 占位 |

**核心矛盾**：功能已具备，**视觉表达力与产品形态不足**——分辨率、字体、控件种类、主题、触屏范式均待补。

---

## 2. 设计目标与原则

1. **双模式同源**——桌面与手机共用平台层，应用代码最大复用；差异仅在交互范式。
2. **视觉先行的实用主义**——在当前硬件约束下做到干净、可读、统一。
3. **控件即语言**——交互收敛到统一控件基元，应用不手绘 UI。
4. **主题可换**——颜色全部收口到 theme，一改全改。
5. **渐进实施**——每个里程碑独立编译、独立真机验收。
6. **开源友好**——图标/字体/配色自绘，不依赖闭源资产。

## 3. 共享平台层设计

### 3.1 分层架构（两个模式共用）

```
┌─────────────────────────────────────────────┐
│  应用层  apps/ (hello/terminal/files/…)      │
├─────────────────────────────────────────────┤
│  ┌───────────桌面模式──────────┐ ┌──────────手机模式──────────┐
│  │ desktop.c + wm.c (窗口系统) │ │ mobile.c (触屏 UI 框架)    │
│  └─────────────┬──────────────┘ └─────────────┬────────────┘
├────────────────┼──────────────────────────────┼─────────────┤
│  控件基元  widgets.c (button/label/input/     │              │
│            list/scrollbar/checkbox/progress)  │              │
├────────────────┼──────────────────────────────┼─────────────┤
│  主题层  theme.c (配色/尺寸/字体统一入口)       │              │
├────────────────┼──────────────────────────────┼─────────────┤
│  图形抽象  vga_gfx.c (画点/线/矩形/字体/双缓冲) │              │
├────────────────┼──────────────────────────────┼─────────────┤
│  输入抽象  keyboard.c / mouse.c / touch.c     │              │
└────────────────┴──────────────────────────────┴─────────────┘
```

### 3.2 图形抽象（升级项）
- 现有 API 保留：`gfx_putpixel/hline/vline/rect/fillrect/line/clear/putchar/puts/flip/vsync`。
- 新增：`gfx_putchar_zh`（中文）、`gfx_draw_icon16`（16x16 图标）、`gfx_gradient`（壁纸渐变）。
- 远期 VBE 升级时，仅替换底层实现，上层坐标 API 不变（分辨率无关抽象）。

### 3.3 输入抽象
- 统一 `hepu_input_event_t`：{类型, x, y, button, key, keycode, 附加压力/手势}。
- 桌面模式消费鼠标/键盘；手机模式消费 touch 事件（按下/移动/抬起 + 双击/长按/滑动手势识别）。

### 3.4 控件基元（widgets.c）
两模式共用绘制与命中逻辑，容器不同（窗口 vs 全屏页）。
- 现有升级：Button（按压/焦点/禁用）、Label（多行/对齐）、Input（光标闪烁/选中/粘贴）。
- 新增：**List**（条目+选中+滚动）、**Scrollbar**（垂直/水平）、**Checkbox**、**ProgressBar**、**Separator**、**Panel/Group**、**Dialog**（模态）。

## 4. 桌面模式（现役 · 开发验证平台）

> 定位：开发驾驶舱，永久保留，鼠标键盘交互。

### 4.1 桌面
- 壁纸：渐变+格点（`wallpaper.c`）。
- 图标：单击选中、双击启动、右键菜单（打开/刷新/关于）。
- 任务栏：窗口按钮 + HEPU + 时钟（已有，升级最大化按钮显示）。

### 4.2 窗口
- 拖动/双击标题栏最大化/最小化/关闭。
- 模态对话框（阻塞底层窗口事件）。

### 4.3 键盘导航
- Tab 循环焦点、Enter 激活、Esc 关闭、方向键列表移动。

### 4.4 终端
- Terminal 升级多行滚动 + 命令历史 + 分页。

## 5. 手机模式（目标 · 触屏 UI 框架）

> 定位：产品形态。`mobile.c` 独立触屏框架，VBE + 触屏就绪后启动（阶段 E）。

### 5.1 屏幕布局（竖屏优先，比例 9:16）
```
┌──────────────────────┐
│ 状态栏 (14px)          │  时间 | 信号 | 电量 | 状态图标
├──────────────────────┤
│                      │
│   全屏应用区          │
│   (占满剩余空间)       │
│                      │
├──────────────────────┤
│ 导航栏 (手势区)        │  返回 | Home | 最近任务
└──────────────────────┘
```

### 5.2 核心组件
| 组件 | 说明 |
|---|---|
| `mobile_statusbar` | 顶部状态栏：时钟、信号、电量、通知点 |
| `mobile_shell` | 应用网格桌面（图标+名称），滑动翻页 |
| `mobile_page` | 全屏应用页容器（无标题栏/无边框） |
| `mobile_gesture` | 手势识别：滑动翻页、下拉通知、长按、双击 |
| `mobile_navbar` | 底部手势导航（或虚拟键） |
| `mobile_kbd` | 虚拟键盘（QWERTY + 数字符号页） |
| `mobile_notify` | 通知下拉面板 |

### 5.3 应用适配
- 应用通过统一 `app_register()` 注册，桌面模式进窗口、手机模式进全屏页，**同一份应用代码**。
- 系统应用规划：拨号（占位）、联系人、设置、文件、终端、便签、相机（占位）、相册（占位）。

## 6. 视觉规范（Theme 体系）

### 6.1 配色方案（默认 "Hepu Blue"）

| 语义 | 索引 | 用途 |
|---|---|---|
| 深蓝黑 | 0 | 壁纸底色 |
| 浅灰 | 7 | 窗口/页面背景 |
| 亮蓝 | 9 | 标题栏激活、选中、焦点 |
| 深蓝 | 1 | 标题栏失活 |
| 中灰 | 8 | 按钮面、边框、分隔 |
| 黑 | 0 | 正文 |
| 白 | 15 | 标题/强调 |
| 红 | 12 | 警告/错误 |
| 绿 | 10 | 成功反馈 |

### 6.2 尺寸体系
| 元素 | 桌面模式 | 手机模式 |
|---|---|---|
| 字体 | 8x8 | 8x16（放大可读性） |
| 标题栏 | 12px | —（全屏无标题栏） |
| 状态栏 | — | 14px |
| 按钮 | 高14px | 高 28px（触控目标 ≥ 7x7mm） |
| 图标 | 32x32 | 48x48 |
| 任务栏/导航栏 | 14px | 18px |

### 6.3 字体与图标
- 内置 **GB2312 常用汉字子集**（512~1024 字，8x16 点阵，约 8-16KB）——UI 全中文。
- 自绘 16x16/32x32 像素图标（文件/文件夹/终端/齿轮/地球/铅笔/拨号/相机/设置），C 数组内置。

## 9. 风险与权衡

| 项 | 说明 |
|---|---|
| 方向 | 当前 GUI 是桌面式=开发驾驶舱，产品形态在手机模式——已在文档明确定位，避免方向误判 |
| 分辨率 | 320x200 是桌面模式当前约束；手机模式依赖阶段 D VBE 升级（真机验证，风险中） |
| 中文点阵 | 512-1024 字≈8-16KB，空间可接受；UTF-8→GB2312 查表需解码器 |
| QEMU 局限 | 键盘/鼠标注入受限、无触摸；渲染可 QEMU 验证，交互需真机 |
| 兼容性 | 控件库独立不改 wm 对外接口；应用 `app_register()` 统一注册，双模式复用 |
