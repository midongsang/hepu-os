# v0.56.2 缺陷修复记录

版本类型：patch（缺陷修复）。触发来源：用户反馈"鼠标点了不灵""任务管理器没有显示占用""天气/状态组件不显示"。

## 一、鼠标点击的层次归属（取证结论）

用户原话是"如果你使用鼠标都不灵，那我更不可能使用成功，要么是输入和代码问题，要么是系统问题"。按分层取证法先证实内核是否真正收到事件，再判定责任层：

| 取证点 | 手段 | 结果 |
| --- | --- | --- |
| XHCI HID 报告解析 | 在 `xhci64.c` 报告解析处临时打按钮字节与报告长度 | QMP 注入后出现 `[XHCI] btn=0x1 raw0=0x1 len=0x4` |
| 输入层分发 | 在 `hsinput.c` 点击分派前临时打按钮合流结果 | 同步出现 `[IN] left=0x1`，释放后回 `0x0` |
| HMP 通道对照 | `mouse_button 1` / `0` | 按钮位始终为 0，`ps2_left=0x0`，即 HMP 的 `mouse_button` 不会送到 `-device usb-mouse`（走 XHCI） |

**结论**：内核的 XHCI 驱动能正确解析按钮位，输入层也能正确合流并分发 —— 输入链路本身没有缺陷。之前"点击不灵"的直接原因是**注入通道选错**（HMP 对 USB 鼠标的按钮无效），只有 QMP `input-send-event` 能打通。取证代码（两处 `TEMP-DBG`）在验证完成后已全部删除，发布版不会刷串口。

## 二、Apps 页图标"看得见、点不到"（真实缺陷）

`hpdesk_handle_click()` 原本只处理三处命中：灵动岛、侧栏标签（Info/Apps/Weather）、底部 Dock。**Apps 页的应用图标网格只实现了渲染，没有任何命中测试** —— 用户切到 Apps 页后逐个点图标毫无反应，这是"鼠标不灵"体验上最直接的一处。

修复：

- 新增 `hs_apps_cell_pos(int i, int *ax, int *ay)`，把网格单元坐标（含滚动与视口裁剪判定）收敛为唯一公式；
- 渲染循环与点击命中**共用该函数**，避免"渲染一套公式、点击另一套公式"造成长期错位；
- `hpdesk_handle_click()` 在侧栏标签之后增加 Apps 图标命中：落在单元内即置 `g_pending_app`，交给 `desktop64` 主循环启动应用；命中框在图标 48×48 基础上左右各放宽 4px，纵向覆盖到名称行。

修复过程中发现并修正的连带问题：初次抽取公式时漏掉了标题 `Applications` 占用的 35px，导致图标整体上移压住标题；已补回该偏移，渲染与命中保持一致。

验证：在 Apps 页对 `hs_apps_cell_pos(7, …)` 算出的单元中心发起点击，串口出现 `[DESKTOP64] Pending app request handled`，任务管理器窗口被创建（窗口槽 `id=1`，`window_count=2`）。

## 三、任务管理器窗口渲染损坏

数据源在 v0.56.1 已接真实统计，但界面仍不可读：

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| CPU/RX/TX 三个曲线区是三块纯黑矩形 | `m_draw_curve()` 把背景硬编码成 `0x000000`，浅色主题下就是黑块 | 背景改 `g_shell.colors.panel_bg`，中线改 `g_shell.colors.border` |
| 曲线区里一条线都看不到 | 折线用 `gfx64_draw_line` 画在窗口内容层上不可见 | 改为按值填充柱状条（`gfx64_fill_rect`，与背景矩形同一原语，已验证可见） |
| 窗口标题条与内容同时出现 "Task Manager" | `m_render()` 内部又画了一次标题 | 删除内部标题，标题只由窗口管理器绘制 |
| 进程列表与底部提示条重叠 | 提示条用 `cy += 2` 跟随列表，列表一长就溢出窗口 | 提示条固定贴 `w->y + w->height - 16` |
| 窗口里找不到"占用"数字 | 只有曲线没有汇总 | 摘要行后新增 `CPU: xx%    MEM: xx%`，与 Info 页、灵动岛同源 |

实测同一 1 核 1GB 实例：`MEM: 41860/1048384 KB  PROC: 1  DRV: 9`、`CPU: 0%  MEM: 3%`、进程表 `0 idle 100% 0 sys`（系统空闲时 CPU 0%，与统计口径一致）。

## 四、灵动岛状态条是写死文案

`hs_dynamic_island_render()` 展开态的系统状态条原为字符串常量 `"CPU 35%  MEM 60%  WiFi On"`，与任务管理器/Info 页的真实数值长期对不上（同一个屏幕两套数字，极易被当成"数据没接"）。

改为运行时拼接 `hs_process_get_cpu_usage()` / `hs_process_get_mem_usage()` 的返回值，与另外两处共用同一统计源。

## 六、遗留

- QEMU 注入通道不稳（同一命令下 `input-send-event` 时好时坏），因此本轮"点图标 → 窗口出现"的最终确认用了直接调用点击入口的自测路径；自测代码已删除。
- 任务管理器进程表只有 `idle` 一项，因为系统当前没有运行用户进程，属事实而非缺陷。
- 物理鼠标在真机上的点击仍未经真机验证（仅 QEMU 环境）。
