# Hepu OS 64位支持设计文档

> 版本：V0.11.0（64位架构升级）
> 目标：从32位（x86/i386）升级到64位（x86_64/AMD64），支持更大内存和存储
> 创建日期：2026-10-09

---

## 一、设计背景

### 1.1 当前状态
- **当前架构**：32位（x86/i386），保护模式
- **物理内存限制**：4GB（PMM硬上限），PAE扩展支持64GB（36位物理地址）
- **虚拟地址空间**：4GB（32位）
- **存储支持**：2TB IDE磁盘（LBA28/48）
- **x86_64骨架**：已有基础实现（2062行），但未集成到构建系统

### 1.2 升级动机
- **内存需求**：现代设备普遍8GB+内存，32位4GB限制成为瓶颈
- **存储需求**：支持大于2TB的磁盘和分区
- **性能提升**：64位寄存器更多、更大的虚拟地址空间
- **安全增强**：SMEP/SMAP/NX位等64位安全特性
- **兼容性**：支持现代64位应用和驱动

### 1.3 设计原则
- **渐进式升级**：保持32位启动链，内核进入64位长模式
- **向后兼容**：支持32位用户态应用（兼容模式）
- **稳定优先**：每个阶段独立验证，不破坏现有32位功能
- **代码复用**：复用现有驱动和子系统，仅修改架构相关部分

---

## 二、64位架构概述

### 2.1 长模式（Long Mode）
- **启用步骤**：PAE → EFER.LME → CR0.PG → 长模式激活
- **子模式**：
  - 64位模式：纯64位执行
  - 兼容模式：运行32位/16位代码

### 2.2 4级页表（PML4）
```
虚拟地址（48位有效）：
┌─────────┬─────────┬─────────┬─────────┬──────────┐
│ PML4[9] │ PDPT[9] │  PD[9]  │  PT[9]  │ Offset[12]│
└─────────┴─────────┴─────────┴─────────┴──────────┘
  47-39     38-30     29-21     20-12      11-0

物理地址：最大52位（4PB）
页大小：4KB / 2MB / 1GB
```

### 2.3 寄存器扩展
- 通用寄存器：16个64位寄存器（RAX-R15）
- 指令指针：RIP（64位）
- 标志寄存器：RFLAGS（64位）
- 段寄存器：仍然16位，但基址/限制在长模式下被忽略（除FS/GS）

### 2.4 系统调用
- **SYSCALL/SYSRET**：快速系统调用指令
- **MSR**：IA32_STAR、IA32_LSTAR、IA32_FMASK、IA32_KERNEL_GS_BASE

## 三、分阶段实施计划

### 阶段1：引导器64位支持（P0）
**目标**：引导器能从32位保护模式切换到64位长模式，并跳转到64位内核入口

**任务清单**：
1. ✅ 检测CPU是否支持长模式（CPUID）
2. ✅ 构建64位GDT（代码段/数据段/TSS）
3. ✅ 构建初始4级页表（PML4），映射内核到高地址
4. ✅ 启用PAE（CR4.PAE）
5. ✅ 启用长模式（EFER.LME）
6. ✅ 启用分页（CR0.PG）
7. ✅ 远跳转到64位代码段
8. ✅ 传递启动信息（内存映射、帧缓冲、命令行）

**验证标准**：QEMU中能成功进入长模式并显示64位内核入口标记

---

### 阶段2：64位内核构建系统（P0）
**目标**：创建独立的64位内核构建目标，能编译出64位内核二进制

**任务清单**：
1. 创建64位链接脚本（`kernel/linker_64.ld`）
   - 内核加载地址：0xFFFFFFFF80100000（高半核）
   - 段对齐：2MB大页
2. 修改Makefile，添加64位构建目标
   - `make kernel64`：编译64位内核
   - CFLAGS：-m64 -mcmodel=kernel -mno-red-zone
   - LDFLAGS：-m elf_x86_64
3. 创建64位内核入口（`kernel/arch/x86_64/entry_64.S`完善）
4. 创建64位内核主函数（`x86_64_kernel_main`）
5. 集成现有x86_64骨架代码

**验证标准**：能成功编译出64位内核二进制文件

---

### 阶段3：64位内存管理（P1）
**目标**：实现完整的64位虚拟内存管理

**任务清单**：
1. 4级页表管理（PML4/PDPT/PD/PT）
   - 页表分配和释放
   - 虚拟地址到物理地址映射
   - 大页支持（2MB/1GB）
2. 物理内存管理扩展
   - 支持大于4GB物理内存
   - 64位物理地址位图
   - NUMA支持（预留）
3. 内核虚拟内存布局
   - 物理内存直接映射区（-2GB空间）
   - 内核代码/数据区
   - 内核堆区
   - I/O映射区
4. 用户态虚拟内存
   - 每个进程独立的PML4
   - 48位用户地址空间（128TB）
5. TLB管理和刷新

**验证标准**：能分配和映射大于4GB的物理内存

---

### 阶段4：64位中断和异常（P1）
**目标**：实现64位中断描述符表和异常处理

**任务清单**：
1. 64位IDT（中断门/陷阱门）
2. 中断入口汇编（保存64位上下文）
3. 异常处理（Page Fault、GP Fault等）
4. APIC中断控制器（64位适配）
5. 系统调用（SYSCALL/SYSRET）

**验证标准**：能处理时钟中断和键盘中断

---

### 阶段5：64位系统调用ABI（P1）
**目标**：定义并实现64位系统调用接口

**任务清单**：
1. 系统调用号定义（与32位兼容或重新编号）
2. 参数传递约定（RDI/RSI/RDX/R10/R8/R9）
3. 系统调用表
4. 32位兼容系统调用（兼容模式）
5. vsyscall/vDSO（快速系统调用）

**验证标准**：用户态应用能调用系统调用

---

### 阶段6：驱动和子系统适配（P2）
**目标**：将现有驱动和子系统适配到64位

**任务清单**：
1. 存储驱动（IDE/AHCI/NVMe）
   - 64位DMA地址
   - LBA48支持（大于2TB）
   - NVMe驱动（64位原生）
2. 网络驱动（RTL8139/e1000/virtio-net）
3. 图形驱动（VBE/VGA/virtio-gpu）
4. 输入驱动（键盘/鼠标）
5. USB驱动（xHCI）
6. 文件系统（ext2/ext4/FAT32/exFAT）
7. 进程调度和IPC

**验证标准**：主要驱动能在64位下正常工作

---

### 阶段7：用户态64位支持（P2）
**目标**：支持64位用户态应用

**任务清单**：
1. 64位ELF加载器
2. 64位C库（musl/newlib移植）
3. 64位系统调用封装
4. 32位兼容层（运行32位应用）
5. 动态链接支持

**验证标准**：能运行64位Hello World应用

---

### 阶段8：更大内存和存储支持（P3）
**目标**：充分利用64位地址空间

**任务清单**：
1. 物理内存支持：最大64TB（52位物理地址）
2. 虚拟内存支持：128TB用户空间+128TB内核空间
3. 存储支持：最大8ZB（64位LBA）
4. 大页支持（1GB页）
5. 内存热插拔
6. 交换分区大于2TB

**验证标准**：能在QEMU中配置16GB内存并正常使用

## 四、内存布局设计

### 4.1 物理内存映射（64位）
```
0x000000000000 - 0x000000000FFF   实模式中断向量表（IVT）
0x000000001000 - 0x00000009FFFF   常规内存（640KB）
0x0000000A0000 - 0x0000000FFFFF   VGA/BIOS区域
0x000000100000 - 0x0000001FFFFF   内核加载区（1MB-2MB）
0x000000200000 - ...              可用物理内存
```

### 4.2 虚拟内存布局（64位，48位有效）
```
0x0000000000000000 - 0x00007FFFFFFFFFFF   用户空间（128TB）
  ├─ 程序代码/数据
  ├─ 堆
  ├─ 共享库
  └─ 栈

0x0000800000000000 - 0xFFFFFFFF7FFFFFFF   非规范区（不可访问）

0xFFFFFFFF80000000 - 0xFFFFFFFFFFFFFFFF   内核空间（2GB）
  ├─ 0xFFFFFFFF80000000 - 0xFFFFFFFF800FFFFF  物理内存直接映射（16MB）
  ├─ 0xFFFFFFFF80100000 - 0xFFFFFFFF801FFFFF  内核代码/数据（1MB）
  ├─ 0xFFFFFFFF80200000 - 0xFFFFFFFF803FFFFF  内核堆（2MB）
  ├─ 0xFFFFFFFF80400000 - 0xFFFFFFFF807FFFFF  I/O映射区（4MB）
  └─ 0xFFFFFFFF80800000 - 0xFFFFFFFFBFFFFFFF  动态映射区（1GB-）
```

### 4.3 与32位布局对比
| 项目 | 32位 | 64位 |
|------|------|------|
| 虚拟地址空间 | 4GB | 256TB（48位有效） |
| 用户空间 | 3GB | 128TB |
| 内核空间 | 1GB | 2GB（高半核） |
| 物理内存 | 4GB（PAE 64GB） | 64TB（52位） |
| 页表级别 | 2级（PAE 3级） | 4级 |
| 页大小 | 4KB/4MB | 4KB/2MB/1GB |

## 五、存储支持扩展

### 5.1 当前限制
- IDE LBA28：最大128GB
- IDE LBA48：最大144PB（当前未完全实现）
- 分区表：MBR最大2TB，GPT最大8ZB

### 5.2 64位改进
1. **完整LBA48支持**：64位扇区地址
2. **GPT分区表**：原生支持大于2TB磁盘
3. **NVMe驱动**：64位原生，支持更大容量
4. **文件系统64位**：ext4/XFS的64位块地址
5. **大于2TB文件支持**：64位文件偏移

## 六、兼容性设计

### 6.1 32位引导链
- 保持现有32位引导器（HepuBoot）
- 引导器加载64位内核后切换到长模式
- 不需要修改MBR和stage1

### 6.2 32位用户态兼容
- 兼容模式运行32位应用
- 32位系统调用转换层
- 32位ELF加载器

### 6.3 驱动兼容
- 大部分驱动代码与架构无关
- 仅需修改DMA地址、寄存器访问等架构相关部分

---

## 七、风险和挑战

### 7.1 技术风险
1. **引导器长模式切换**：需要精确的寄存器和页表设置
2. **64位内核调试**：调试工具和方法需要调整
3. **驱动适配**：部分驱动可能有32位假设
4. **性能优化**：64位指针更大，可能增加内存占用

### 7.2 缓解措施
1. 每个阶段独立验证，不破坏32位构建
2. 保留32位内核作为回退选项
3. 充分利用QEMU进行测试
4. 详细的文档和错误记录
