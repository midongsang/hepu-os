# 赫普OS开发优先级规划

> 制定日期：2026-09-21
> 基于当前状态：内核V1.02稳定 / 引导器V6.46稳定 / Rust用户态验证成功 / 文本模式正常 / 图形模式未实现

## 优先级总览

| 优先级 | 阶段 | 时间 | 核心目标 | 关键成果 |
|--------|------|------|----------|----------|
| **P0** | 基础夯实 | 1-2周 | 消除技术债务，验证图形模式 | mobile.c重构完成 / gfxtest验证 / hepu-sys完善 |
| **P1** | 核心能力 | 1-2月 | 图形子系统+网络栈+Rust服务试点 | 基础绘图API / Socket API / 文件服务Rust化 |
| **P2** | 开发体验 | 2-4月 | 标准库+调试工具+API文档 | musl移植 / GDB支持 / 完整系统调用文档 |
| **P3** | 生态建设 | 4-6月 | UI组件库+第三方库+示例应用 | 按钮/输入框组件 / zlib/libpng移植 / 记事本应用 |
| **P4** | 高级特性 | 6月+ | 应用商店+安全机制+多语言 | 应用分发 / 沙盒机制 / Python运行时 |

## P0：基础夯实（1-2周）

**目标**：消除已知技术债务，为后续开发扫清障碍。

### P0-1：mobile.c代码重构（最高优先）
- **现状**：4668行，远超合理范围（建议<2000行）
- **任务**：按功能模块拆分为多个文件（调度/内存/IPC/进程管理）
- **验收**：每个文件<2000行，编译通过，功能不变
- **风险**：拆分可能引入回归bug，需每次拆分后跑三级验证

### P0-2：图形模式（gfxtest）验证
- **现状**：只有文本模式，图形模式未验证
- **任务**：
  1. 编写VESA BIOS扩展检测代码
  2. 实现简单的线性帧缓冲绘图（像素/矩形/线条）
  3. 编写gfxtest应用验证图形模式
- **验收**：QEMU中能显示彩色图形（非文本模式）
- **依赖**：无（可独立进行）

### P0-3：hepu-sys库完善
- **现状**：只有基础系统调用，分配器不支持free/realloc
- **任务**：
  1. 实现内存分配器的free和realloc
  2. 实现nanosleep系统调用（替代yield循环）
  3. 添加更多系统调用封装（mmap, ioctl, fcntl）
  4. 实现简单的字符串处理函数
- **验收**：Rust应用能动态分配/释放内存，能精确睡眠
- **依赖**：内核需支持nanosleep系统调用

### P0-4：Rust示例应用扩展
- **现状**：只有hello-rust一个示例
- **任务**：
  1. 文件读写示例（open/read/write/close）
  2. 简单的cat工具（读取文件并输出）
  3. 简单的echo工具
- **验收**：3个Rust应用能正常运行
- **依赖**：P0-3（hepu-sys完善）

## P1：核心能力（1-2月）

**目标**：实现开发软件必需的核心系统API。

### P1-1：图形子系统基础（最优先）
- **现状**：只有文本模式，是开发软件的最大障碍
- **任务**：
  1. 基础绘图API：点、线、矩形、圆形、位图绘制
  2. 双缓冲机制（避免闪烁）
  3. 简单的窗口管理（创建、移动、关闭、Z轴顺序）
  4. 字体渲染（内置点阵字体，后续支持TrueType）
- **验收**：能创建多个窗口，在窗口中绘制图形和文字
- **依赖**：P0-2（图形模式验证）

### P1-2：网络协议栈完善
- **现状**：有ARP/DHCP基础，缺少Socket API
- **任务**：
  1. 完善TCP/IP协议栈（TCP状态机、拥塞控制）
  2. 实现BSD Socket API（socket/bind/listen/accept/connect/send/recv）
  3. 实现DNS解析
  4. 实现简单的HTTP客户端
- **验收**：应用能通过HTTP获取网页内容
- **依赖**：无（可与图形子系统并行）

### P1-3：输入系统统一
- **现状**：键盘/鼠标输入分散处理
- **任务**：
  1. 统一输入事件模型（键盘、鼠标、触摸事件）
  2. 实现输入事件队列
  3. 实现输入法框架基础（拼音输入雏形）
- **验收**：应用能通过统一API获取键盘和鼠标事件
- **依赖**：P1-1（图形子系统需要输入支持）

### P1-4：Rust用户态服务试点
- **现状**：只有Rust示例应用，无实际服务
- **任务**：
  1. 选择文件服务（file-server）用Rust重写
  2. 建立Rust与C的IPC通信规范
  3. 验证Rust服务的稳定性和性能
- **验收**：文件服务用Rust实现，功能与C版本一致
- **依赖**：P0-3（hepu-sys完善）

## P2：开发体验（2-4月）

**目标**：完善开发工具链和文档，降低开发者门槛。

### P2-1：标准库支持
- **现状**：无标准C库，应用需直接调用系统调用
- **任务**：
  1. 移植musl或newlib到赫普OS
  2. 实现POSIX兼容层（常用函数）
  3. 实现C++标准库基础（STL容器）
- **验收**：简单的Linux C应用能直接编译运行
- **依赖**：P1-2（网络栈需要标准库支持）

### P2-2：调试工具
- **现状**：只有串口输出调试，无符号级调试
- **任务**：
  1. 实现GDB远程调试支持（gdbstub）
  2. 实现内核符号表解析
  3. 实现简单的性能分析工具（类似perf）
  4. 实现内存泄漏检测
- **验收**：能用GDB断点调试内核和用户态应用
- **依赖**：无（可独立进行）

### P2-3：API文档完善
- **现状**：有15个文档，但缺少系统调用级别的详细文档
- **任务**：
  1. 编写完整的系统调用文档（每个调用的参数、返回值、示例）
  2. 编写库函数文档（标准C库、图形库、网络库）
  3. 编写开发指南（从入门到精通）
  4. 编写最佳实践（性能优化、安全编码）
- **验收**：新开发者能通过文档独立开发应用
- **依赖**：P1（核心API稳定后才能写文档）

### P2-4：构建系统完善
- **现状**：Makefile可用，但缺少包管理
- **任务**：
  1. 实现简单的包管理器（类似pacman）
  2. 实现依赖自动解决
  3. 支持CMake构建
- **验收**：能通过包管理器安装第三方库
- **依赖**：P2-1（标准库）

## P3：生态建设（4-6月）

**目标**：建立应用生态，吸引第三方开发者。

### P3-1：UI组件库
- **现状**：只有基础绘图API，无高级组件
- **任务**：
  1. 实现常用控件：按钮、输入框、列表、菜单、对话框
  2. 实现布局管理器（水平/垂直/网格布局）
  3. 实现主题系统
- **验收**：能快速构建带UI的应用
- **依赖**：P1-1（图形子系统）

### P3-2：第三方库移植
- **现状**：无第三方库
- **任务**：
  1. 移植zlib（压缩）
  2. 移植libpng（PNG图片）
  3. 移植libjpeg（JPEG图片）
  4. 移植openssl（加密）
  5. 移植curl（HTTP客户端）
- **验收**：应用能使用这些库
- **依赖**：P2-1（标准库）

### P3-3：示例应用
- **现状**：只有基础示例
- **任务**：
  1. 记事本（文本编辑）
  2. 计算器
  3. 文件管理器
  4. 简单的浏览器（基于HTTP客户端）
  5. 简单的游戏（贪吃蛇/俄罗斯方块）
- **验收**：5个完整应用能正常运行
- **依赖**：P3-1（UI组件库）

### P3-4：动态链接支持
- **现状**：只支持静态链接
- **任务**：
  1. 实现共享库支持（.so）
  2. 实现动态加载器
  3. 实现插件系统
- **验收**：应用能动态加载共享库
- **依赖**：P2-1（标准库）

## P4：高级特性（6月+）

**目标**：完善高级功能，建立完整生态。

### P4-1：应用商店
- 官方应用商店（应用分发、更新、评分）
- 开发者后台（应用上传、统计、管理）
- 支付系统（付费应用、内购）

### P4-2：安全机制完善
- 细粒度沙盒（按功能模块授权）
- 系统调用过滤（seccomp类似机制）
- 加密API（AES、RSA、SHA）
- 安全存储（密钥管理）
- 安全审计日志

### P4-3：多语言运行时
- Python运行时（脚本语言支持）
- JavaScript引擎（Web应用支持）
- Go支持（云端应用）

### P4-4：游戏生态
- SDL移植
- 游戏引擎移植（Godot）
- 游戏开发工具

## 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 图形子系统开发难度超预期 | 高 | 阻塞P1/P3 | 先实现最小可用（线性帧缓冲+简单窗口），逐步完善 |
| Rust服务与C内核IPC复杂 | 中 | 延迟P1-4 | 先使用简单的消息传递，后续优化 |
| 标准库移植工作量大 | 中 | 延迟P2 | 先实现常用函数子集，逐步完善 |
| 开发者参与度低 | 中 | 影响生态建设 | 完善文档和示例，降低入门门槛 |
| 硬件兼容性问题 | 低 | 影响实际部署 | 优先在QEMU验证，后续支持真实硬件 |

- **P3阶段**：50%UI组件库 + 30%第三方库 + 20%示例应用
- **P4阶段**：按需求灵活分配
