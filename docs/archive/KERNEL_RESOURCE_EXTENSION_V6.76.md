## 一、设计背景与目标

### 1.1 背景

赫普OS作为自研微内核操作系统，随着功能不断完善（图形子系统、网络协议栈、应用商店、Rust用户态服务等），原有的资源上限已成为系统扩展的瓶颈：

- 物理内存仅支持256MB，无法满足桌面级应用需求
- IDE存储仅支持128GB，不符合现代存储设备容量
- 虚拟显存仅16MB，高分辨率图形模式下捉襟见肘
- 进程数、文件描述符等系统表项限制偏保守

### 1.2 设计目标

1. **可扩展性**：资源上限提升至现代操作系统主流水平
2. **向后兼容**：小内存设备上自动降级，不强制高配置
3. **动态适配**：根据检测到的硬件资源自动调整分配策略
4. **性能稳定**：扩展后不引入性能回退或稳定性问题
5. **可配置性**：关键参数可通过编译选项或启动参数调整

## 二、内存子系统扩展

### 2.1 物理内存支持：256MB → 4GB

#### 设计方案

采用**位图页帧管理**，通过扩展位图存储数组支持更大地址空间。

```c
// kernel/mm/pmm.c
// V6.75: 256MB支持
static uint32_t memory_bitmap_storage[(256UL * 1024 * 1024 / 4096) / 32 + 8];

// V6.76: 4GB支持
static uint32_t memory_bitmap_storage[(4096UL * 1024 * 1024 / 4096) / 32 + 8];
// 4GB / 4KB = 1,048,576 页
// 1,048,576 / 32 = 32,768 个uint32 = 128KB 位图
```

#### 关键参数

| 参数 | V6.75 | V6.76 | 说明 |
|------|-------|-------|------|
| 最大物理内存 | 256MB | **4GB** | 位图覆盖范围 |
| 页大小 | 4096B | 4096B | 保持不变 |
| 最大页帧数 | 65,536 | **1,048,576** | 4GB/4KB |
| 位图大小 | 8KB | **128KB** | BSS段静态分配 |
| 内存区域数 | 16 | 16 | 保持不变 |

#### 兼容性设计

- 位图采用静态分配，不依赖运行时内存分配
- 实际可用内存由multiboot/UEFI启动信息决定，位图仅表示可管理范围
- 小内存设备上未使用的位图区域保持清零，不占用额外资源

### 2.2 内核堆动态分配：5级自适应

#### 设计方案

根据检测到的物理内存总量，动态选择内核堆大小，避免小内存设备上堆占用过多资源。

```c
// kernel/arch/x86/kernel_init.c
uint32_t heap_size = 128 * 1024 * 1024;  // 默认最大值
if (mem_kb < 128 * 1024)       heap_size = 8 * 1024 * 1024;    // <128MB → 8MB
else if (mem_kb < 256 * 1024)  heap_size = 16 * 1024 * 1024;   // <256MB → 16MB
else if (mem_kb < 512 * 1024)  heap_size = 32 * 1024 * 1024;   // <512MB → 32MB
else if (mem_kb < 1024 * 1024) heap_size = 64 * 1024 * 1024;   // <1GB → 64MB
// ≥1GB → 128MB
```

#### 分级策略

| 物理内存 | 内核堆大小 | 占比 | 适用场景 |
|---------|-----------|------|---------|
| <128MB | 8MB | ~6% | 嵌入式/虚拟机 |
| <256MB | 16MB | ~6% | 低配设备 |
| <512MB | 32MB | ~6% | 主流设备 |
| <1GB | 64MB | ~6% | 中配设备 |
| ≥1GB | 128MB | ~12% | 高配/桌面 |

### 2.3 zram内存压缩：256KB → 1MB

#### 设计方案

扩展zram压缩页存储容量，提升内存交换效率。

```c
// kernel/arch/x86/kernel_init.c
zram_init(256);  // V6.76: 256页 = 1MB压缩存储
// 典型压缩率2:1 ~ 4:1，可解压约2-4MB数据
```

#### zram参数

| 参数 | V6.75 | V6.76 | 说明 |
|------|-------|-------|------|
| 压缩页数 | 64 | **256** | 4倍扩展 |
| 压缩存储 | 256KB | **1MB** | LZ4算法 |
| 可解压数据 | ~0.5-1MB | **~2-4MB** | 典型压缩率 |
| 压缩算法 | LZ4 | LZ4 | 保持不变 |

## 三、存储子系统扩展

### 3.1 IDE/ATA磁盘容量：128GB → 2TB

#### 设计方案

利用LBA48寻址能力，将模拟磁盘容量扩展至2TB。

```c
// kernel/drivers/drivers_real.c
drv.disks[0].total_sectors = 4ULL * 1024 * 1024 * 1024;  // 4G扇区 × 512B = 2TB
drv.disks[0].size = 2ULL * 1024 * 1024 * 1024 * 1024;      // 2TB
drv.disks[0].lba48_supported = 1;
```

#### 磁盘参数

| 参数 | V6.75 | V6.76 | 说明 |
|------|-------|-------|------|
| 最大磁盘容量 | 128GB | **2TB** | LBA48理论上限144PB |
| 扇区大小 | 512B | 512B | 保持不变 |
| 总扇区数 | 268M | **4G** | 2TB/512B |
| LBA48支持 | 是 | 是 | 48位寻址 |
| 根分区大小 | 12GB | **100GB** | 示例分区表 |
| EFI分区 | 512MB | 512MB | 保持不变 |

## 四、显存子系统扩展

### 4.1 VVRAM虚拟显存：16MB → 64MB（动态降级）

#### 设计方案

默认配置64MB虚拟显存，但采用**动态降级机制**：当kmalloc分配失败时，自动尝试更小的尺寸，确保在任何内存配置下都能成功初始化。

```c
// kernel/drivers/virtual_vram.c
uint32_t try_sizes[] = {
    virtual_size,      // 请求大小（默认64MB）
    32*1024*1024,      // 降级1: 32MB
    16*1024*1024,      // 降级2: 16MB
    8*1024*1024,       // 降级3: 8MB
    4*1024*1024,       // 降级4: 4MB
    2*1024*1024        // 降级5: 2MB（最低保证）
};
```

#### VVRAM参数

| 参数 | V6.75 | V6.76 | 说明 |
|------|-------|-------|------|
| 默认虚拟显存 | 16MB | **64MB** | VVRAM_DEFAULT_SIZE |
| 最大区域数 | 8 | **16** | 物理+虚拟显存区域 |
| 最大句柄数 | 256 | **512** | 显存分配句柄 |
| 块大小 | 4KB | 4KB | 保持不变 |
| 动态降级 | 无 | **6级** | 自动适配内存 |

#### 降级策略验证

在86MB内存的QEMU环境下：
- 请求64MB → kmalloc失败
- 尝试32MB → kmalloc失败
- 尝试16MB → kmalloc失败
- 尝试8MB → kmalloc失败
- **尝试4MB → 成功**
- 最终VVRAM可用：4MB，自测7/7通过

### 4.2 显示模式支持

| 模式 | 分辨率 | 色深 | 帧缓冲大小 | 说明 |
|------|--------|------|-----------|------|
| VGA文本 | 80×25 | 16色 | 32KB | 0xB8000 |
| VGA图形 | 320×200 | 256色 | 64KB | 0xA0000 |
| VBE/SVGA | 800×600 | 32bpp | ~1.9MB | LFB线性帧缓冲 |
| VBE/SVGA | 1024×768 | 32bpp | ~3MB | 优先模式 |
| GOP(UEFI) | 1024×768 | 32bpp | ~3MB | QEMU+OVMF默认 |

> 高分辨率模式（1920×1080等）需要更大帧缓冲，VVRAM 64MB配置可满足。

### 进程内存开销估算

```
每进程开销 = 内核栈(16KB) + 用户栈(64KB) + process_t(~256B) + 页目录(4KB)
           ≈ 84KB

128进程总开销 ≈ 128 × 84KB ≈ 10.5MB
在4GB内存系统中占比 < 0.3%
```

## 七、统一内存架构

### 7.1 三种内存类型

赫普OS采用统一内存管理器（umem），支持三种内存类型自动分配：

```c
// kernel/include/unified_mem.h
#define UMEM_TYPE_NORMAL      0  /* 普通物理内存 */
#define UMEM_TYPE_VRAM        1  /* 显存 */
#define UMEM_TYPE_COMPRESSED  2  /* 压缩内存（zram） */
```

### 7.2 分配策略

```
应用请求内存
    │
    ├─ 小尺寸(<64KB) → 普通内存（快速访问）
    ├─ 图形数据 → 优先显存（VVRAM）
    ├─ 冷数据/缓存 → 压缩内存（zram）
    └─ 大尺寸 → 普通内存，内存不足时降级到压缩内存
```

## 十一、经验总结

1. **静态位图是扩展内存支持的最简方案**：不引入伙伴算法等复杂机制，位图即可覆盖4GB
2. **动态降级是兼容性的关键**：大默认值 + 自动降级 = 高配设备享受大资源，低配设备不崩溃
3. **资源扩展要同步更新所有相关表项**：进程数、FD数、Socket数需要协同扩展
4. **BSS段增长可控**：128KB位图对于现代系统微不足道，但带来16倍内存支持提升
5. **小内存环境仍是重要测试场景**：86MB QEMU环境有效验证了降级逻辑的正确性
